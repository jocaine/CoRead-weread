CoRead 详细说明与故障排查
================================================
（先看外层那份 README-FIRST.txt，这份是出问题时才用的）


■ 完整目录结构

    CoRead\
    ├── README-FIRST.txt           一分钟上手
    ├── data\                      ★你的全部数据（备份就复制这一个文件夹）
    │   ├── README.txt                这一格是干什么的：备份、哪些能删、密钥在哪
    │   ├── config\                   ★设置：API 地址、模型名、密钥（含密钥，别外发）
    │   ├── profile\                  ★画像、价值观侧写、知识图谱
    │   ├── sessions\                 ★聊天记录、讨论进度、会话流水账
    │   ├── reading\                  ★划线标注、书库缓存（读过的章节原文）
    │   ├── runtime\                  运行状态（可以随时删，程序会自己重建）
    │   └── toolbox\                  ★翻译记录
    ├── extension\                 浏览器插件 ★装插件时选这个目录
    ├── internal\                  程序本体（这里**不放**你的数据）
    │   ├── Start-CoRead.vbs          ★启动入口（双击这个）
    │   ├── node.exe                  运行环境（不用单独装 Node）
    │   ├── tray.ps1                  托盘程序
    │   ├── stop.bat                  兜底退出
    │   ├── unblock.bat               解除"来自互联网"标记
    │   ├── instructions-zh.txt       本文件
    │   ├── agent\                    共读引擎
    │   │   ├── index.js  lib\        代码（lib\paths.js 决定数据落在哪）
    │   │   └── scripts\              维护脚本（含数据迁移脚本）
    │   └── receiver\                 接收端（只有代码，没有数据）
    ├── builtin\                   随程序分发的内置图谱（不是你的数据）
    └── logs\                      运行日志

  启动入口为什么是 .vbs 而不是 .bat：
    双击 .bat 时 Windows 会用 cmd.exe 去跑它，而 cmd 是控制台程序 —— 必然闪一个
    黑窗口（旧版本还会停 8 秒）。.vbs 由 wscript.exe 执行，那是图形程序，
    不会有任何窗口，托盘也因此能完全隐藏启动。文件内容是可读的纯文本，
    想核对可以右键 →「编辑」。

  带 ★ 的就是你的个人数据，全部在 data\ 下。
  备份 = 复制 data\ 这一个文件夹；搬家 = 把它拷到新包的同一个位置。
  为什么这么分：以前数据散在 internal\ 的好几个子目录里，备份得对着说明书一个个找，
  很容易漏（漏一个游标，程序会把半年前的对话当成新的重跑一遍）。

故障排查
════════════════════════════════════════════════

【弹出"安全警告 / 无法验证发布者"】

  这是 Windows 的"网络来源标记"（从网上下载的 zip 会带）。
  不是病毒提示，也不是杀软拦截。

  处理：双击  internal\unblock.bat  一次，之后不再弹。
  （或：右键 internal\Start-CoRead.vbs →「属性」→ 勾「解除锁定」→ 确定）


【杀毒软件报警，说"未知程序修改系统设置"】

  本程序没有购买数字签名证书（开源个人项目，费用较高），所以火绒、
  360、Windows Defender 等可能拦它。

  这是误报。原因只有一条：
    · 共读引擎（node.exe）需要在后台常驻运行 —— 杀软把"一个不知名的程序
      一直在后台跑着"当成可疑行为

  本程序**不写任何注册表自启项**，也不改系统设置（2026-10 核实：全项目没有
  一处写注册表的代码）。所以如果杀软说"修改系统设置"，那是启发式误判。

  处理：杀软弹窗里选「允许」并勾「记住本次操作」。
  火绒最省事的做法：安全工具 → 信任区 → 把整个 CoRead 文件夹加进去。

  想核对程序做了什么：internal\agent\ 和 internal\receiver\ 里的 .js
  都是可读的纯文本，没有编译过的二进制。


【双击 Start-CoRead.vbs 后，托盘没出现图标】

  1. 打开  logs\ ，看 tray.log / agent.out.log / receiver.out.log
  2. 最常见原因：端口 7239 被占用（之前启动过一份没关干净）
     解决：先运行 internal\stop.bat，再重新双击 internal\Start-CoRead.vbs
  3. logs 里写了"启动失败"，把日志内容发到项目 issues


【双击 Start-CoRead.vbs 完全没反应（连弹窗都没有）】

  先确认入口文件还在：internal\Start-CoRead.vbs
  再看 logs\tray.log 有没有新内容（起来了就一定会写）。

  另一种可能：这台机器把 VBScript 组件关掉了（Win11 24H2 起它是"可选功能"，
  将来默认不启用）。检查办法：设置 → 系统 → 可选功能 → 看列表里有没有
  VBScript；没有就点「添加功能」装上，然后重新双击。


【装浏览器插件 / 在选择框里找不到 extension 目录】

  插件只需要装一次。完整三步在外层 README-FIRST.txt 的「第 2 步」。

  最省事的做法：右键托盘图标 →「装浏览器插件」。
  它会把  <包根>\extension  的完整路径复制到剪贴板、在资源管理器里把这个
  目录选中给你看，并弹一个三步说明。

  各种浏览器的入口不一样，但都逃不出这两处：
    · 地址栏右边的拼图块形状图标 →「管理扩展程序」
    · 右上角菜单（三个点 / 三条横线）→「扩展程序 / 扩展管理」
  怎么知道找对了页面：它列着已装的扩展，并且有「开发者模式」开关。
  只有 Chrome 与 Edge 能靠地址直达（chrome://extensions/ 与
  edge://extensions/）；其余内核浏览器的地址各不相同，别去猜。

  按钮的措辞各家不同（Edge 上就不叫「加载已解压的扩展程序」），
  认作用就行：那个让你选一个本地文件夹的按钮。

  在选择框里迷路时：选择框上方有一个输入框，把路径粘贴进去（Ctrl+V）
  再回车，就直接跳到 extension 目录了。

  两条硬限制（是浏览器的安全边界，不是本程序的问题）：
    · 浏览器不能从 zip 装插件，只能走「加载未打包 / 已解压的扩展程序」
    · 不能把文件夹拖到扩展页上装 —— 拖拽只对 .crx 安装包有效

  常见报错：
    "Manifest file is missing or unreadable"（清单文件缺失或无法读取）
      → 选错层级了。要选中 extension 目录**本身**，
        不是它的父目录，也不是它里面的 vendor 或 icons。


【哪些浏览器能用 / 装上了却没有侧栏】

  CoRead 的侧栏用的是 Chromium 的 side_panel 接口。这类接口在各个内核
  分支上实现得并不完全一致，所以要分两件事看：

    能装      所有 Chrome 内核浏览器都能"加载未打包的扩展"：Chrome、
              Edge、Brave、Vivaldi、360 极速、QQ、猎豹……
    能用      侧栏还需要 side_panel 接口。已知 Chrome 与 Edge 支持；
              其余分支（Opera、Vivaldi、部分国产浏览器）是否实现需要
              实测 —— 如果装上了却怎么也调不出侧栏，多半就是它。
    Firefox   用不了。Firefox 的侧栏是另一套机制（sidebar_action），
              与 side_panel 不通用。

  真实缺口（2026-10 记录，尚未修）：插件在缺少 side_panel 的浏览器上
  **不会给任何提示**（extension/service_worker.js 里是 .catch(() => {})
  静默吞掉），表现就是"装上了、但侧栏永远不出现"，很难自己排查。
  另外 extension/manifest.json 写的 minimum_chrome_version 是 102，
  而侧栏用的接口比它新（具体起始版本待核实）—— 也就是说中间那一段
  版本的浏览器会被允许安装，却永远看不到侧栏。打算补一条能力检测提示。


【浏览器侧栏一片空白 / 显示未连接】

  说明插件没连上本机程序。检查：
  1. 托盘图标还在不在（可能被误退了）
  2. 浏览器访问  http://127.0.0.1:7239/books
     能返回内容 = 程序正常；打不开 = 程序没在跑


【想退出】

  右键托盘图标 →「退出 CoRead」（会先让共读引擎保存本次记忆再退，
  所以可能要等几秒）。

  说明：CoRead **不会开机自启** —— 每次开机后要自己双击
  internal\Start-CoRead.vbs 启动。（这样它不会在你不知情的时候常驻。）


【彻底卸载】

  1. 托盘右键 →「退出 CoRead」
  2. 浏览器扩展页把 CoRead 移除
  3. 删掉整个 CoRead 文件夹

  注意：3 会连你的阅读记录一起删掉（就是上面 ★ 标的 data\ 文件夹）。
  想留着就先复制一份 data\。


【从旧版本升级上来，聊天记录是空的】

  2026-10 起数据集中到 data\ 了；更早的版本把数据散在 internal\ 里，
  老数据不会自动搬过来。跑一次迁移即可（先演练、再真搬）。

  注意命令要用**包里自带的 node**（这台机器上没装 Node，直接敲 node 会报
  "不是内部或外部命令"）。在包根目录打开命令行，逐条执行：

      internal\node.exe internal\agent\scripts\migrate-data-layout.mjs
      internal\node.exe internal\agent\scripts\migrate-data-layout.mjs --apply

  第一条是演练：只打印"准备搬哪些文件"，一个都不动。看过没问题再跑第二条。

  迁移是"先复制、校验字节数、通过才删源"，中途失败不会丢数据；关键文件
  （聊天库、图谱、讨论栈）还会留一份 .pre-migrate 备份。跑之前请先退出 CoRead，
  否则文件被占用会失败。

  搬完之后旧位置可能还留着一些残渣（老格式流水、调试日志、.bak，实测可能有
  几百 MB）。想腾空间就跑一次：

      internal\node.exe internal\agent\scripts\migrate-data-layout.mjs --clean-legacy

  它会先列出清单和体积，确认后才删。

  程序启动时也会自动体检：发现旧数据没搬，会在 logs\agent.out.log 里提示你，
  并给出上面这条命令。
