CoRead —— 一分钟上手
============================================================

【放哪里】很重要，先看这条

  不要把整个文件夹放进 C:\Program Files！
  那里受系统保护，程序写不进自己的数据，会启动失败。

  放到这些地方都可以：
      D:\CoRead
      C:\Users\你的用户名\CoRead
      桌面、文档、其他盘的普通文件夹

  （已经在 Program Files 里了？整包剪切出来就行。）


【怎么用】三步

  第 1 步  双击  internal\Start-CoRead.vbs

           （是个 .vbs 文件，不是 .bat。Windows 自带的脚本，作用就是"隐藏启动"——
            所以双击它不会闪出黑窗口。杀软若提示，允许即可。）

           右下角托盘会出现一个图标。右键它可以：
             打开微信读书 / 打开数据文件夹 / 退出 CoRead

  第 2 步  装浏览器插件

           浏览器地址栏输入，回车：  chrome://extensions/
           （Edge 用 edge://extensions/）

           ① 打开右上角「开发者模式」
           ② 点「加载已解压的扩展程序」
           ③ 选中本文件夹里的  extension  目录   ← 就是旁边那个

  第 3 步  填模型 API Key

           打开微信读书网页版，右侧会出现 CoRead 侧栏。
           点侧栏右上角「⋯」→「模型 API 配置」，填入 API 地址、
           API Key、模型名，保存即生效。


【你的数据在哪】

  都在  data  文件夹里（就是旁边那个，托盘右键「打开数据文件夹」也能跳过去）：

      data\config\     设置：API 地址、模型名、密钥（含密钥，别外发）
      data\profile\    阅读画像、价值观侧写、知识图谱
      data\sessions\   聊天记录、讨论进度
      data\reading\    划线标注、书库缓存（你读过的章节原文）
      data\runtime\    运行状态（可以随时删，程序会自己重建）
      data\toolbox\    翻译记录

  备份：复制  data  这一个文件夹，就是完整备份。
  搬家：把 data 文件夹拷到新电脑的同一个位置（和 internal 同级）。
  彻底删除：先退出 CoRead，再删掉整个程序文件夹。
  哪一格能删、哪一格不能删：data\README.txt 里写清楚了。


【出问题了】

  双击 Start-CoRead.vbs 没反应、也没弹提示
      → 先确认文件在  internal\Start-CoRead.vbs（不是被移走了）
      → 再看 logs\ 里的 tray.log（有错会写在这儿）
      → 系统若提示"无法打开此文件"，说明这台机器禁用了 VBScript 组件：
        设置 → 系统 → 可选功能 → 添加功能 → 搜 VBScript 装上

  看到"无法验证发布者"的安全警告
      → 双击 internal\unblock.bat，之后不再弹。

  杀毒软件报警（火绒/360/Defender）
      → 误报。本程序没买数字签名证书。在弹窗里选「允许」并记住；
        火绒可以把它加进「信任区」。原因和自查方法见详细说明。

  双击后托盘没出现图标
      → 打开 logs\ 看日志；或先跑 internal\stop.bat 再重试
        （常见原因是端口被上一份没关干净的进程占着）。

  更详细的排查：internal\instructions-zh.txt


【其他文件】

  data\         你的全部数据。要备份就复制它，别的都不用管。

  internal\     程序本体（Node 运行环境、引擎、接收端、说明书）
                入口就是这里的 Start-CoRead.vbs，双击它启动。
                想核对程序做了什么可以放心看——里面的代码都是可读的
                纯文本 JavaScript，没有编译过的二进制。
                这里**不放你的数据**，程序升级覆盖它不会碰到你的记录。

  builtin\      随程序分发的内置图谱（用户数据缺失时图视图显示它）。不用管。

  logs\         运行日志，只在排查问题时才需要看。
