# 内置教程书：设计

> ⚠️ **这份设计已废弃（2026-10-20）。** 产品决定改成"一本真的 PDF"：
> 教程由作者排版成 `coread使用教程.pdf`，作为普通书籍放进阅读器书库（第一批书之一），
> 内置的《第一次共读》、课程引导（`extension/tutorial/`、`tutorial-script.js`、
> `tutorial-guide.js`、预设例句、教程专用会意图种子）**整套删除**。
> 本文件只作为决策历史保留——它记录的取舍（为什么当初做成"书不是帮助页"、
> 书 ID 为什么必须是固定常量、图文与动画的边界）在换方案时仍值得读一遍。
> 书稿真源：`docs/tutorial-book/manuscript.md`（导出成 PDF 后放进书库）。

**一句话**：装完插件，侧栏「已读书籍」里就有一本《第一次共读》，用我们自己的阅读器打开；
它是真书（能划线、能提问、AI 按进度读到哪算哪），其中四章不是静态图文，而是把 CoRead
自己的操作流程动画演一遍。

---

## 1. 它为什么是一本「真书」，而不是一个帮助页

三个功能不是白送的，是做成书才有的：

| 白送的东西 | 靠什么成立 |
|---|---|
| 用户能用**划词共读**去问教程本身 | 教程书有 `chapters\*.txt`，agent 照常按划线原文找正文（`agent/index.js:435-489`） |
| 侧栏里它是「当前在读的书」 | 阅读器推快照时带上它的 bookId，侧栏 `applyBookReaderSnapshot` 直接采用（`extension/sidebar.js:1164`） |
| 用户划的线、聊的天，是**他自己的记录** | 存在 `data\reading\books\<书ID>\`，与别的书同构，不是彩页 |

**明确接受的代价**：教程书必须是「可读的文本」，不能是纯动画。动画章节也得有能读的正文与
`chapters\` 切片，否则第一条就废了。

---

## 2. 书的身份怎么定（这是最容易埋雷的一步）

阅读器现在的书 ID 是**内容哈希**：`rd_` + PDF 的 SHA256（`extension/reader.js:144`）。
教程书没有 PDF，但**不能因此发明第二种 ID 形态**——三处校验会当场把它拦掉：

| 校验点 | 规则 | 文件 |
|---|---|---|
| 接收端归一化 | `^[a-f0-9]{16,64}$` | `receiver/index.js:370` |
| 接收端共读侧 ID | `^rd_[a-f0-9]{32,64}$` | `receiver/index.js:407` |
| 侧栏书籍上下文 | `^[A-Za-z0-9_]{12,}$` | `extension/sidebar.js`（`applyBookContext`） |

**处理**：把书 ID 定成**一个固定的 64 位十六进制常量**——内容取
`sha256('CoRead 使用手册 v1')` = `e0c91cb6aa56dd0057235ba7374c03e599e1e37e09b3bc9f55f64e1a5b98a25e`。
它天生满足上面三条，三处校验一个字都不用改。副作用也是好的：它长得跟别的书 ID 一模一样，
不会在书单里显得特殊。

## 3. 内容放哪、笔记放哪（决定「删了就回不来」这类问题的答案）

| | 放哪 | 为什么 |
|---|---|---|
| **手册正文**（章节 + 动画脚本） | `extension/tutorial/book/`，随扩展发 | 升版本时正文跟着版本走，不会被旧数据卡住；用户删不掉 |
| **用户的划线 / 提问 / 讨论** | `data\reading\books\rd_e0c9…\` | 是用户数据，照常参与备份、照常能被书单和聊天记录引用 |
| **`chapters\*.txt`**（给 AI 看的切片） | 接收端登记时从**手册正文字块**导出 | 一处真相：改正文不会漏改切片；正文永不进 `data\`，不会被误删 |

**为什么不放 `builtin\`**：那个目录被打包脚本强制要求**完全为空**
（`installer/pack-portable-zip.ps1:535-545`，2026-10 为「作者的私人图谱曾被本地打包带出去」
而立）。要往里放东西就得改那道闸门，而这份内容本来就该跟着扩展走——**不动闸门**。

**明确接受的代价**：正文写死在扩展里，用户想改教程内容改不了（不打算支持，想改就是改代码）。

---

## 4. 阅读器怎么同时装下 PDF 和教程书

阅读器现在整篇假定「文档 = pdf.js 的 PDF」：页面容器、缩放、页码、译文锚点、扫描件判定、
框选翻译、懒渲染队列，全部长在 `state.doc` 上。**不是加一个分支就完事**，所以做法是：

1. 把「当前这本是什么」收进一个**统一状态**（文档类型 / 书 ID / 书名 / 总页数 / 当前页）。
   这一处是硬要求，不是整理癖——`notesSnapshot()`（`extension/reader.js:1076`）判断
   「你有没有在读一本书」看的就是 `state.doc`；教程书不占住它，侧栏就不认这本书，
   引用与提问全部没有归属。
2. PDF 那条路原样不动，只是读写这个统一状态；
3. 教程渲染器**单独一个模块**（`extension/tutorial/render.js`），阅读器只调它的四个接口：
   打开 / 关闭 / 跳章 / 快照。动画全部关在那个模块里，不污染阅读器的渲染循环。
4. 顶部工具栏按文档类型切换：教程书里「框选翻译」「适宽」「缩放」「已渲染 N/M 页」这些
   PM 才成立的东西**隐藏**——留着点不动比没有更糟。页码位置改成章名。

**动画形态**：每章一张「书页」，页内切分成上下两栏——**上面演，下面读**（正文）。这样一屏
之内「看见操作」和「读懂它在干嘛」同时在场，不用来回滚。

## 5. 演示用的界面从哪来（防「demo 越用越假」）

手画一套假侧栏最省事，也最容易三个月后跟真界面对不上。所以：

- **侧栏演示**：克隆**真的** `sidebar.html` 里的 `#no-book-view` / `#ref-current` / `#msgs`
  等片段，套真的 `sidebar.css`，用假数据驱动；交互步骤用加类名的方式演（与真侧栏同一套类名）。
- **会意图演示**：会意图是 canvas 画的（`extension/graph-view.js:1339` 起），没法克隆 DOM。
  这里**不复制力导向布局**——只借它那几个颜色常量（根标记 / 引用标记 / 边色），在教程自己的
  canvas 上画十来个节点与边。视图是「像」的，不是「同一份代码」，这条诚实写在设计里。

**闸门**：自测里比一次「演示片段用到的 id/类名，在真 `sidebar.html` 里都存在」。真界面改了名
而演示没跟上，自测当场红——**不靠人记得同步**。

## 6. 动画怎么演、怎么不出事

每章的动画写成一段**声明式步骤表**（谁、什么时候、加什么类、说什么话），由渲染器逐条播：

- **进入视野自动播一次**，离开视野复位；有「重播」按钮，也能点进度条跳到某一步。
- 切片（「划词的那一下」）用纯 CSS 过渡做，不用 canvas，也不用动画库。
- 任何计时器在**离开视野 / 关章 / 关页**时清掉：一本会自己跑的说明书最忌讳切走了还在后台跑。

## 7. 它怎么出现在「已读书籍」里

阅读器打开教程书时，照 PDF 那条路一样报一次名（`/reader-book`，`receiver/index.js:1563`）：
接收端写下 `meta.json` + 导出 `chapters\`，书单就有了它。**复用现成接口，不加新接口。**

**明确接受的代价**：接收端没起来时，书单里没有它（但教程照常能打开、动画照常能播）。
这与「PDF 在接收端没起来时也能看」是同一条规矩，不特殊处理。

**版本更新**：手册正文跟着扩展走，所以升级后用户看到的永远是新版教程；他的划线/讨论在
`data\` 里不受影响。改动正文导致的锚点偏移不做迁移（代价：旧划线可能落偏，接受）。

## 9. 实施中踩到的坑（都已修，记下来免得重踩）

1. **书 ID 抄在三处**：写错一个字符不会报错，只会让接收端把章节导到另一个目录、而 agent 去原目录找
   → 用户在教程里划线提问得到"未找到对应章节"。所以第一道闸门就是比对源码里的三处常量。
2. **注入的真样式一行都没生效**：片段里的 id 为了避免撞车改过名（`msgs` → `tut-d-msgs`），
   而注入的选择器还写着 `#msgs`。**样式不匹配不会报任何错**，演示只是悄悄退化成浏览器默认样子。
   → 选择器必须跟着 id 对照表一起改名；自测里加一条 `el.matches('.tut-sk #<它的 id>')` 的断言。
3. **作用域类不能复用带外观的类**：把片段的标签类写成底座那个 `.tut-frame-inner`，
   结果 `#msgs` 继承了底座的 `width: 600px`，气泡右侧被裁掉一半。→ 作用域类必须是纯标签。
4. **作用域类要挂在共同祖先上**：加在片段自己身上时 `.tut-sk #tut-d-msgs` 匹配不上（作用域是后代选择器）。
5. **`hidden` 不能无条件摘**：摘掉之后 `/收口` 命令菜单、「选择文件」全冒出来了。只摘片段根自己的。
6. **`play()` 不能写成 `async`**：函数体等一个微任务才跑，而 `sync()` 先把按钮刷回去了，
   表现是"按钮写着播放、动画一动不动"。
7. **一次点击不能被处理两次**：`restart()` 内部会调 `play()`，而点击处理里四个并列 `if` 导致
   同一次点击又被 `stop()` 掉。→ 一个动作一条路。
8. **`play()` 只置 `playing` 不落到第 0 步**：`pump()` 的守卫把 `at === -1` 读成"已播完"，当场自停。
9. **演示容器固定高度 + 真样式里气泡容器是 flex 但没写 `align-items`**：气泡被拉满整列（477×520）。
   这在真侧栏里看不出来（消息区是自然高度），只在演示这种固定高度里暴露。
10. **说明条压在迷你界面上**，正好挡住输入框和发送键。→ 改成排在界面下方。

其中 2、3、4、9、10 只有**真跑起来量一次尺寸 / 截一张图**才发现得了，静态检查与类型检查全都发现不了。

## 11. 第二轮（2026-11，用户三条反馈）

### 反馈 1：「点第一次共读，阅读器没有自己弹出来」

**这不是坏，是从来没有这条动作。** 侧栏书单里"点一本"一直只做"手动选书 → 看它的讨论记录"，
而 `rd_` 开头那几本（我们阅读器放进去的书）连一个"去读"的入口都没有。

补的链路：侧栏 → 后台 `openReaderBook` → 开/切阅读器标签页并带上 `?open=<hash>` → 阅读器读这个参数自己取原件。
- 阅读器里的书，整行点击 = **去读**（那才是用户点它时想干的事）；微信读书的书仍然是看记录。
- 书单里给阅读器里的书多一枚「读」按钮：**有没有这枚按钮，本身就是"这本能不能在这儿读"的答案**。
- 顺手修了一个潜伏问题：`setTranslationRef`（划词/译文设为引用）没写"待选引用"标记，
  侧栏**之后**才打开时那条引用不会被自动选中。阅读器里划词点共读正好走这条路。

### 反馈 2：「说有七章，但无法切换到后面章节，没有找到入口」

**页码以前只是显示，从来不是入口。** 顶栏加「目录」，三种内容按"有没有真章节"降级：
1. 教程书 → 书自带的章节表（这本是我们写的，章节确定）
2. 有书签的 PDF → pdf.js 的 `getOutline()`，**真书签**，按树渲染（`getPageIndex` 把页对象引用换算成页号）
3. 其余的 PDF → 只剩页码滑杆 + 一句"这本没有书签目录"

**明确不做**：不靠字号/编号猜章节。猜错的目录比没有目录更烦人，而且没法向用户解释那条"章节"为什么落在那儿。

### 反馈 3：「我要的不是自动播放的动画，像游戏那种教程」

这是最实质的一条，也是我上一轮理解浅了：我做的是**看它演**（自动播放的录像），
用户要的是**让你做**（游戏新手关）。所以新增一层"引导模式"，与原有的页面内演示并存：

| | 页面内演示（demo.js） | 引导模式（tutorial-guide.js + tutorial-script.js） |
|---|---|---|
| 在哪 | 教程书那一页里，缩小的界面 | **真实侧栏**上，界面照常 |
| 干什么 | 演一遍流程，讲"长什么样" | 高亮一个真实控件 + 说一句"点这里"，讲"你现在该点哪" |
| 推进 | 按时间轴自动走 | **必须真的做那一下**；点错会被抖一下并重新提示 |
| 出口 | 重播 / 跳到某一步 | 跳过这步 / 退出教程 |

六步脚本全部落在真实链路上，没有一步是假动作：

1. 在阅读器里划中一段正文（真的造选区 → 浮出「共读」）
2. 点「共读」（真的走 `setTranslationRef` → 接收端 `/annotation(setRef)` → 侧栏设为当前引用）
3. 看「当前引用」卡（点它跳到原文位置才算做完）
4. 在输入框里打字（只点不打字不算）
5. 点发送 → 等消息区出现新气泡
6. 点 ◎ 看会意图 → 走完

三条设计约束：
- **不可跳过关键动作**：每步盯着真实事件，没做就不走；但每步都留「跳过这步」——没有出口的教程会把人卡死。
- **等待类步骤不假装成功**：第 5 步等 AI 回复，取决于用户配没配模型；没配就照实说，不自己往下走。
- **状态放 `chrome.storage`**：侧栏页面每次打开都是新会话，放内存里的话用户一去阅读器划词、回来教程就没了。

### 第二轮踩到的坑

11. **自测里重复用同一份 PDF 字节**：pdf.js 把 ArrayBuffer **转移给 worker**，原 buffer 变 detached；
    第二次拿它开会抛错 → 走 failOpen → 文档变 null，后面一长串断言全塌。
12. **换书时排队中的那次保存会丢**：`setTimeout(saveRecord, 600)` 读的是**那 600ms 后**的 state，
    于是防抖窗口内换书，那一笔要么写到新书键上、要么被 `if (!hasBook()) return` 丢掉。现在排队时就把"写给谁"定下来。
13. **造带书签的测试 PDF 时**：中文标题必须写成 UTF-16BE 十六进制串（PDF 的普通字符串是 Latin-1，直接写会乱码）；
    书签的 `/Next` 要指向**下一个同级**（我写成"紧邻的下一条"，pdf.js 顺链只读出两条就断了）。
14. **目录断言不能"数条数"**：中间还开过别的书，条数会时灵时不灵。改成按内容哈希查"当前这本在不在"。

## 13. 第一次真实自检的结果（2026-11-09）：三个真 bug

用户点了一次自检，报告回来 14/28。**先对版**：16 个文件指纹与仓库**逐字一致** →
排除"没生效"，剩下的都是真问题。这一节记的就是它们，都是**只有真环境跑得出来**的那种。

### ① `selfcheckEval` 忘了 `return true` → 调用方拿到空对象 `{}`

reader.js 的消息监听里，`runSelfcheckEval` 是 `async`，我写成：

```js
if (msg.action === 'selfcheckEval') { sendResponse(runSelfcheckEval(msg, sender)); return }
```

`runSelfcheckEval` 返回的是 **Promise**，得等它 resolve 才有值。而监听函数一返回，
消息通道就关了 —— 之后的 `sendResponse` 落进空处，**调用方收到一个空对象 `{}`**，
不抛错、不留痕。报告里那一连串 `{}` 全是这一行。

修法：`Promise.resolve(...).then(sendResponse)` 并 **`return true`** 保持通道。
配套：自检侧把"空对象"单独认出来并报出原因（`阅读器回应为空对象 —— 通常是那边没在
异步响应前 return true`），否则下次还是只剩一个空括号。

### ② 自检的 `checks` 数组跨次累积 → "54 项"其实是两次运行叠加

`checks` 是模块级的，`run()` 开头没清空。同一页面上跑第二遍时，报告里是 27+27=54 项，
**上一次的失败项混进来**，看起来像"这次又坏了"。
是自测夹具连跑四次把这个逼出来的（第 1 遍正常、第 2 遍起就翻倍）。
修法：`run()` 开头 `checks.length = 0`。

### ③ 两条断言本身是错的：`?open=` 不是"该留着"的东西

我拿"标签页 URL 里应该留着 `?open=<书ID>`"当断言，白报了两条假失败。
**阅读器的设计恰恰是打开完就把它抹掉**（`history.replaceState`，为的是刷新页面不重复打开）。
而用户实测"点书会弹出阅读器"与后台回报的 `action: "update tab 744315485"` 完全对上——
第 1 条反馈本来就是好用的。

修法：**弃用 URL 当判据**，改成轮询"阅读器页面自己报它活着吗"（`__readerTest`）。
兜底导航的触发条件也从"URL 不对"改成"阅读器没活"。

### 顺带修掉的

- `openReaderBook` 里 `chrome.windows.update` 的异常会污染返回值（"找到了标签页"被当成"没找到"）→ 拆开，
  并新增 `action` 字段如实回报走了哪条路（`update tab N` / `create tab N`）。
- URL 拼装抽成纯函数 `buildReaderBookUrl`：**能被自测直接喂数据验**（大小写归一化、非法输入返空、带书名编码）。
  原先的静态闸门是按字符串找 `reader.html') + '?open='`——重构一次就误报，属于脆断言，一并换掉。
- 后台第一次有了 debug 上报（`reportDebug`）：这条链路只能靠用户点，**日志是唯一的现场记录**。

## 14. 第二次真实自检的结果（2026-11-09）：CSP 把动态求值拦死了

用户又跑了一次，报告回来 15/27。这回失败信息**自己说出了原因**（这正是上一轮加"把原因带回报告"的回报）：

```
阅读器拒绝执行：Evaluating a string as JavaScript violates the following
Content Security Policy directive ... script-src 'self'
```

### ④ MV3 的 CSP 禁止 `new Function` —— 而夹具查不出来

自检驱动阅读器的方式是"发一段表达式过去、那边 `new Function` 求值"。**扩展页面的 CSP 是
`script-src 'self'`，动态求值一律被浏览器拒绝**，于是阅读器那十几项全报"拒绝执行"。

最难受的不是这个 bug，是**它为什么能活到我这儿**：夹具是普通网页、`serve.mjs` 只给
`/extension/*` 加了那行 CSP 头，所以夹具里一路绿灯。

修法两条，缺一不可：
- 阅读器改成**操作表**（`SELFCHECK_OPS`）：只接受操作名（`alive` / `tocOpen` / `selectParagraph` …），
  不执行任何传入的代码。顺带把门关得更死——现在能进来的只有名字。
- `serve.mjs` 把那条 CSP **也加给 `/selftest/*`**，夹具再想"本地过、上线挂"就当场现形。
  （代价：夹具页里的内联脚本会被拦——两个夹具随即改成外部脚本，这也正是真扩展的规矩。）

### ⑤ 自检的 `checks` 数组跨次累积

`run()` 开头没清空模块级的 `checks`，同一页跑第二遍就是 27+27=54 项，**上一次的失败混进新报告**。
是自测夹具连跑四遍逼出来的。

### ⑥ 我自己的测试运行器也会骗我

`drive.mjs` 在"页面入口没起来"时**非零退出且不写报告**，而我读的是 `last-report.json` ——
读到的其实是**上一轮的陈旧文件**，于是一片绿。为此加了一个统一的跑批脚本
（`test/scratch/run-all-suites.mjs`）：每套都看**退出码**，非零直接标红，绝不读陈旧报告。
另外静态闸门也补了"扩展代码里不许有动态求值""夹具必须带同一条 CSP""夹具页不许有内联脚本"三条。

## 16. 合起来：书与引导变成一件事（2026-11 用户定调）

用户在自检全绿之后说："动画指导什么的还是不对"。问清之后选了 **B：书里的动画和侧栏的引导是两张皮，应该合起来**。

### 上一版错在哪

两套东西各演各的：

| | 书里（`.tut-demo` + `demo.js`） | 侧栏里（`tutorial-script.js`） |
|---|---|---|
| 干什么 | 一个缩小的假界面**自动播** 3–6 步，配一句说明 | 在真界面上高亮，**要你动手** |
| 用户角色 | 看 | 做 |
| 例子 | "看，引用卡出现了" | "去左边划一句，浮标会出来" |

问题是**它们互不认识**：书里演完不会把你推去做，侧栏里做完也不知道你在书的哪一章。用户读完一章不知道自己该干什么，做了半天也不知道对应书里哪一节。

### 合起来的样子

**一章 = 一课**：

```
书里读正文（讲清"是什么、为什么"）
   ↓  点「开始本课」（书里那块卡片）
侧栏把你按真界面带一遍（引导状态写在 storage 里，侧栏没开也接得上）
   ↓  走完
书翻到下一章
```

### 三条设计决定

1. **课程的"真源"只有一份**：`extension/tutorial/lessons.js`。书用它决定"这章有没有课、按钮写什么"，
   侧栏用它决定"这一课几步、每步盯哪个控件"。两边各写一份必然会飘（书里说有课、侧栏里没有）。
2. **"讲一句"和"要你做"分成两种步骤**：`read` 类给「继续」按钮，`wait` 类必须真做
   （点控件 / 打字 / 等新气泡）。把讲一句也写成等待，用户会盯着屏幕等一个永远不会自己跳的步骤。
3. **没有课的章节就老老实实是文章**（第 1 章"先说右边那一栏"、第 7 章"你的东西放在哪"）。
   不必每章都塞一个互动——硬塞出来的互动比没有更糟。

### 代价（明确接受）

- **删掉了两万字节的成品代码**：`tutorial/demo.js`（迷你界面 + 时间轴）、`tutorial/scope-css.js`
  （从真 sidebar.html 里抽样式）、以及 `tutorial.css` 里那一整套舞台/坐标系/.tut-frame
  （430 行 → 212 行）。这些都是上一版为"演一遍"专门做的，现在没有用途了。
  留着的唯一理由是"以后可能还想演"，而留着它的代价是每次改真侧栏都要同步它——不值。
- **侧栏必须可见才能上课**。所以书里那块卡片在点了之后会**如实说**"引导在右侧侧栏，
  没开着就点一下工具栏图标"（侧栏一打开会自动接上，因为状态在 storage 里）。
  不假装成功——这是这一版反复强调的那条：不能让人对着一个没反应的东西等。
- `chrome.sidePanel.open()` 需要用户手势，手势能不能穿过消息传到后台**各版本行为不一致**，
  所以自检里把 `opened` 如实回报，失败也算"报告说清楚了"，不算失败。

## 17. 侧栏没被带起来：两个错叠在一起（2026-11 用户实测）

用户点「开始本课」之后说"右侧栏没有把我带起来"。日志里只有后台一条记录：

```
15:45:56 / 15:46:52  open-side-panel-lesson  opened=false
  error=`sidePanel.open()` may only be called in response to a user gesture.
```

**手势不会穿过 `sendMessage` 从阅读器页传到后台。** 这是浏览器的安全边界，不是 bug——
但它只是原因之一，真正让整条链路失效的是下面这个：

### ⑧ 广播挂在"打开成功"之后 → 侧栏开着也收不到

后台那个函数原先是「先 open()，再广播」。而 open() 实测**每次都失败**，于是广播被一起带走了：
**侧栏明明开着、明明在等通知，却什么也收不到**。功能其实是可用的，只因为顺序写错而整条失效。

修法两条：
1. **广播无条件先发**，与能不能打开完全无关；而且发两次（侧栏刚打开时脚本可能还没就绪）。
2. **打开之前先查 `chrome.runtime.getContexts()`**——侧栏已经在的话根本不需要 open()，
   也就不会白报一个失败给用户看。只有真需要开、又开不了时，才如实告知。

### ⑨ 侧栏那个「教程」按钮传的参数是旧签名

`script.start({ bookId })` → 合并之后签名改成了**课号**。忘了改这里**不会报错**：
`Number({})` 是 NaN，被 `|| 0` 兜住，于是永远开第 1 课——静默走错。

### 这一轮的教训：跨上下文的链路，每一步都要留痕

用户报"没反应"时，日志里**只有后台那一条、侧栏那边完全空白**，于是分不清是
"广播没送到"还是"送到了但起不来"。补上侧栏侧的三条 debug 记录
（`tutorial-lesson-ping` / `-loaded` / `-restored`）之后，这类问题一次就能定位。

同一个道理也适用于自检：新增两条真环境探针——
**快捷键到底注册上没有**（写错的表现是 `chrome://extensions/shortcuts` 里显示"未设置"、
按下去毫无反应）、**调用时侧栏是否已经开着**。

### 写闸门本身也踩了两个坑（记下来）

- `sidebar` 这个名字在 `check-tutorial.mjs` 里指的是 **sidebar.html**，而新串在 **sidebar.js** 里——
  于是写出两条永远为 false 的闸门。
- 找 `open()` 不能全文件 `indexOf`：文件前面还有两处别的 `sidePanel.open` 调用，
  先命中就永远判错。要**先切出函数体再找**。

这两条都属于"闸门自己写错"，而闸门写错的代价比没有闸门更大：它会报假失败，把我引去改没坏的东西。

## 18. 还是没效果：真正的原因是我读错了对象的形状

用户重试后仍然没效果，但**这一轮的日志一次就定位到了**（因为上一轮刚补了侧栏侧的三条记录）：

```
16:03:57  sidebar  tutorial-lesson-ping      chapter=2
16:03:57  sidebar  tutorial-lesson-loaded    hasRestore:false     ← 就是这里
16:03:57  sidebar  tutorial-lesson-restored  ok:false
16:03:57  open-side-panel-lesson             opened=true
```

链路全通、侧栏也开起来了，**断在 `hasRestore:false`**。

### ⑩ `loadTutorial()` 返回 `{guide, script}`，我读成了 `t.restoreRun`

```js
loadTutorial().then((t) => t && t.restoreRun && t.restoreRun())   // ❌ t.restoreRun 是 undefined
```

`loadTutorial()` 返回的是 **`{ guide, script }`**，`restoreRun` 在 **`t.script`** 上。
于是那个条件永远为假、永远不接课——**不报错、只是没反应**，和前面几个坑一模一样的形态。

修法：`t.script.restoreRun()`，并把 `t` 的真实形状（类型 / 键名 / `script` 的键名）一起报进日志，
下次同类问题一眼就能分开"形状不对"和"模块没导出"。

### 教训：诊断信息要**足够区分**，否则等于没有

"接课失败"这件事有两个完全不同的原因（形状不对 / 存储里没状态），而原来只回报一个 `ok:false`。
这一轮把两边都补上：
- 侧栏侧报 `t` 的形状 + `hasRestore`；
- `restoreRun` 内部报 `found / active / lesson / ageMs / keys`。

结果一次跑就看清了。**"加日志"不是可选项，是这类跨上下文链路的必需品**——
它们断了都不报错，日志是唯一的现场。

### 自测补上了那段本该覆盖它的场景

夹具里新增「侧栏被关掉再打开」：写状态 → 换一个新模块实例 → `restoreRun()` → 断言卡片上写着
"第 2 课 · 1 / 3"。**这段路以前没有任何自测覆盖**，而它恰恰是断掉的那一段。

写这条测试时又踩了一个：一开始先 `stop()` 再 `restoreRun()`，而 `stop()` 的语义是"用户退出教程"，
它会**把状态从存储里删掉**——等于自己把要验的东西删了。而"关侧栏"不删状态（真实场景是页面被销毁，
存储原封不动）。诊断里那个 `store: null` 就是它，也是靠"把读到的东西打出来"才看出来的。

教程终于能带人了，用户提了四条。四条里有三条是**设计问题**，不是实现问题。

### ⑪ 更新扩展后一打开侧栏，教程自己冒出来

根因是两件事叠在一起：状态存在 `chrome.storage` 里**跨会话有效**，而侧栏**每次打开都
`restoreRun()`**——于是任何一次打开都可能把一条旧记录接起来，看起来像插件坏了。

修法两条锁，缺一不可：
- **侧栏启动只显示「继续教程」入口，不自动开课**。`restoreRun()` 遇到暂停态返回 `'paused'`，
  由用户点「继续」才 `resume()`。这是"教程不该自己冒出来"与"中途关掉别丢进度"的取舍点。
- **扩展启动即作废那份状态**（SW 冷启 / `onStartup` / `onInstalled` 三处）。
  教程是"你开始才存在"的东西，不该活过一次扩展的全生命周期。
  代价是"浏览器重启后不能接着上次"——明确接受，因为"教程自己冒出来"更糟。

顺带修了一个隐蔽的判据错误：`at`（最后活动时间）原来只在开始/换步时写，用户在第 3 步
认真操作很久（正合教程本意）反而会让记录被判成"很久以前"丢掉。改成每次存都刷新。

### ⑫ 第 2 步"没有可以操作的地方，只能点跳过"

两步都错在我：判据要求"点 📍 跳到原文"，而用户**是从阅读器划完词过来的，人就在原文那儿**——
跳什么？他确实无事可做。

改成一件真做得到的事：**换一条引用**。判据也从"有内容"改成"**内容变了**"
（`refFilled` → `refChanged`）——否则引用卡里本来就有内容，这一步会被瞬间跳过。

配套还解决了一个更普遍的问题：**遮罩只挖一个洞**，所以"要你点 A"的时候界面上别的东西全点不动。
现在支持多洞，并且带 `data-guide-pin` 的元素**任何一步都不压暗**（引用抽屉、
「继续教程」条）。自测里有一条探针专门验这个：放一个被标记的元素，算一遍遮罩矩形，
断言它没被盖住（实测：洞从 1 个变 2 个，遮罩块从 4 块变 7 块，探针通过）。

### ⑬ 预先准备好引用和会意节点，且**只在教程里显示、不混用户的**

用户点名了两条边界：会意节点不能是全局的；教程的会意图**不能显示用户自己的节点**。

所以走完全隔离的一条路：
- 数据是扩展自带的 `extension/tutorial/graph-seed.json`（5 个节点 4 条边，对应第 3、4 章讲的那几条讨论）
- 接收端只在 `?tutorial=1` 时读它，**默认那个 `/graph` 一个字都不碰**；读不到就返回空图，
  **绝不回退**到用户的图（一回退就等于把用户的节点混进来了）
- 侧栏在打开图之前按"当前书是不是那本手册"决定请求哪一种
- 图上打「教程样例」标签，明说它不是用户的图

实测：`/graph?tutorial=1` 返回 5 个节点，用户的 139 个节点里**一个教程节点都没混进去**。

引用样例同理：`lessons.js` 里的 `SAMPLE_REFS` 只在教程书里、只进"切换引用"抽屉，
**不调 `addRecentAnn`**（不进用户的引用库）。第 2 步那个"换一条引用"用的就是它们。

### ⑭ 在教程书里点「切换引用」回到了选书界面

`jumpToAnnotation` 整条路都是为**微信读书**写的（per-base 找 weread tab、按章节槽位定位）。
`rd_` 书既不在 weread tab 里、也没有槽位，于是被当成"找不到的书"，用户看到的就是选书界面。

修法：在函数开头把 `rd_` 书**拦下来**，走后台那条现成的"打开阅读器里的某一本"，
并支持 `&chapter=<n>` 直接翻到那一章（深链原来是打开上次那一章，用户会以为跳错了）。

## 20. 最贵的一课：把"版本"变成可观测的

用户又报了两条（第 2 步还是不对；切换引用仍回主界面），两条都**已经修过**。
查日志才发现真相：

```
最近三条 open-reader-book 记录的字段：source,stage,reused,action,hash,url,timestamp,receivedAt
有 chapter 字段吗: false        ← 我加的代码会写它
```

**他机器上跑的还是旧代码。** 扩展要手动重新加载才生效，而"当前跑的是哪一版"
在任何地方都看不出来。于是每一轮都变成：我改 → 他试 → 呈现旧行为 → 我再猜。
这比任何一个具体 bug 都贵。

### 修法：侧栏每次打开就上报构建指纹

`sidebar.js` 的 `reportBuildStamp()` 把 10 个关键文件的 SHA-256 前 6 字节写进 debug 日志，
`test/scratch/check-build-stamp.mjs` 拿它与仓库逐个比，直接报"哪几个文件对不上"。
从此"你跑的是哪一版"是一个**可查询的事实**，不再靠推断。

### 顺带的两件真事

- **第 2 步按用户的定调重写**："第一步用户自己随便引用完之后，让他切换到**我们为他准备的**"。
  原来那一步只要求"换一条"，现在文案与例句都指向准备好的那组，并且点明"点「切换引用 ▸」，
  抽屉最上面是「教程例句」"。
- **引导卡片支持自己的极简标记**（`**强调**` 与 `<br>`）。踩过：`body` 用的是 `textContent`，
  于是卡片上直接印着 `**我准备的例句**` 和 `<br>`。实现时**先转义再放标记回来**——
  课程表虽是静态文件，但没理由留一个"以后有人往里写用户输入就出事"的口子。

### 诊断字段的原则（这轮总结）

**宁可信里多写字段，不要少写。** `chapter` 传 0 时被 `JSON.stringify` 省略，
我因此判定"用户跑的是旧版本"——判断本身对了，但**依据是错的**（缺字段只说明没写，
不说明版本旧）。现在两处日志都显式写 `chapter: Number(msg?.chapter) || 0`。

## 21. 第 2 步定稿：例句必须"长在引导卡片上"

用户重载之后跑了一次（**指纹 10/10 一致，确认跑的是最新代码**——这一步很关键，
它把"版本问题"彻底排除掉，剩下的都是真问题），又提了两条：

1. "第二步骤的时候我发现你在这里没有给我事先准备好引用"
2. "点击了切换引用之后你的高亮也应该贴着切换引用栏"

### 例句：从"去抽屉里找"改成"卡片上的按钮"

上一版让用户点「切换引用 ▸」、再在抽屉里挑一条。问题是**那批例句的可见性依赖好几件事**：
侧栏认不认得出当前是机械教程书、样例模块加载完没有、抽屉渲染时机。任何一环不满足，
用户看到的就是一个空抽屉——而他只能点"跳过"，这一步就白设计了。

**定稿做法**：`lessons.js` 里那四条 `samples` 直接渲染成引导卡片上的按钮，点一下调
`window.__coreadPickSampleRef(text)`（侧栏导出的真实"选引用"路径：`pickReference`），
引用立刻换成那一条，`refChanged` 随之推进。抽屉那条路保留着当"另一种做法"教，
但**不再依赖它**才能过这一步。

顺带两处：
- 例句按钮**不截断文字**（截了用户不知道自己在选什么），靠 `.tg-wide` 独占一行换行。
- 把"选引用"抽成 `pickReference()`：原来只有抽屉里那一条 DOM 处理器会这么干，
  别处想选一条只能再写一遍——而"再写一遍"必然分叉（一边清了待选标记、另一边忘了）。

### 高亮：抽屉打开时要跟着挪

原来目标一直钉在引用卡上，而抽屉是盖在界面上的另一层——高亮框和一整片抽屉**错位**，
用户看到的是"高亮框在讲一个你已经看不见的东西"。

修法：打开抽屉时调 `guideFollowDrawer()`，把高亮挪到抽屉的**标题条**（不是整个抽屉——
圈整个抽屉时那个框会盖住它自己的内容，看着像故障）；关掉抽屉再挪回引用卡。
**只在本步确实和引用有关时才挪**（目标是 `ref-current` / `rc-switch-btn`）：
其他步骤打开抽屉属于用户自己乱点，那时把高亮挪走反而让他找不着原来的目标。

挪位要重画卡片，于是踩到一个变体坑：`Guide.showStep` 是 `replaceChildren`，
重画时**忘了带按钮就会丢处理器**（卡片上只剩"退出教程"）。所以把上一次的按钮组存在
`lastActions` 里，重画时原样带上。

## 22. 第 2 步三轮才定稿，以及"自检要能问侧栏"

用户重载后（指纹 10/10 一致）又说"还是不行"，并明确要求：
**"你怎么没有把第二步的那些按钮去掉"**、**"你不要自己在这猜测了，你给我再弄一点自检"**。

### 那排按钮是我越改越偏

| 轮次 | 第 2 步长什么样 | 用户反馈 |
|---|---|---|
| 1 | "点 📍 跳到原文" | 他人在原文那儿，**没有可操作的地方**，只能点跳过 |
| 2 | "随便换一条引用" | 应该是"**切换到我们为他准备的**" |
| 3 | 例句做成**卡片上的按钮** | "**把第二步的那些按钮去掉**" |

第 3 轮他说得对：这一步要教的就是**「切换引用」这个操作**，把例句摆到卡片上等于**绕过它**。
定稿：例句只在侧栏抽屉里（那才是"切换引用"的正经路径），卡片上只有跳过/上一课。
万一抽屉那条路真坏了，卡片上**不塞按钮**，而是直说"预设例句没读出来（这是教程的 bug）"——
用户知道该报什么，我也一眼知道该修哪儿。

### 真正的 bug：第 1 步的判据把第 2 步替做完了

日志里 `drawer-open` 在 21:04:41、跳转在 21:04:53，中间**没有任何"换了引用"的记录**。
原因：第 1 步的判据是"引用卡里有内容"，而用户**在第 1 步就填过它了**——
于是他进入第 2 步的那一刻条件立刻成立，**第 2 步被瞬间跳过**，他根本没看见那一步。

修的时候又踩一个（自测当场逮到）：第一版改成"必须先见过空、再被填上"。
看着能治，实际更糟——**引用卡里若有旧内容**（上一课残留），它就永远等"先变空"，
而用户不会去清空，于是**卡死在第 1 步**。
定稿判据：**进入这一步之后，引用卡的内容发生过一次变化**（必须重划一次，但不必先变空）。

### "再弄一点自检"：把侧栏问一遍

前面几轮我一直在**用日志反推**"用户点了哪个按钮、抽屉里到底有没有例句"——查得慢，还猜错过。
现在加了一个探针通道（`coreadTutorialProbe`）：自检直接问侧栏，一次拿到
例句数据读到没、抽屉里渲染出几条、当前书认出来没、教程走到第几步、引用卡上有哪些按钮。

配套两条纪律（都是踩过的）：
- **探针字段必须加进落盘列表**。我算出了 `sidebarProbe` 却忘了往报告里写，
  报告里就是 `undefined`——等于"自检自己把证据丢了"，跟以前那个空 `{}` 同一类毛病。
- **侧栏没开着时不会有回音**，所以探针带 2.5 秒超时，如实回报"没问到"，不假装成功。

### 第一次真的用上它：报告里两条失败，两条都是我的错

用户跑了一次自检，`36/38`。两条失败都不是功能坏了：

1. **`sendResponse is not defined`** —— 侧栏那个消息监听器的参数列表里**没有 `sendResponse`**
   （原来是 `(msg) => {...}`），我在里面直接用了它。这是实现疏忽，但**只有真跑才现形**
   （夹具的替身不会模拟"真浏览器里的监听器签名"）。
2. **"写进去的是第 2 课"失败** —— 断言写错了：第 2 章对应课程表里的**第一课**（下标 0），
   我却断言 `lesson === 1`。

第 2 条值得单独记，因为它暴露了一个更坏的形态：**替身是照着那条错断言填的**
（`selfcheck-harness-setup.js` 里写 `lesson: 1`），于是**替身与断言互相印证了同一个错误**，
两边一起绿。这类"自洽的错误"最难看——唯一能戳穿它的是真环境。
现在的做法：断言用 `lessonIndex(2)` 现算，替身也按同一规则填，不再写死数字。

### 读取自检报告的坑（也记一下）

我自己的读取脚本读了 `logs/selfcheck.json`，而那是**旧接收端时代的残留文件**（14:54），
于是我一直看到一份"27/27 全过"的旧报告，跟当下的失败完全对不上。
**一个"更权威的旧文件"比没有文件更坏**：它会把最新的现场盖掉。
现在按**时间戳**在两份来源（`selfcheck.json` 与 `debug.jsonl` 里那条降级记录）之间取最新，
并且把那份残留删了。


### 另外修掉一条真的会丢位置的 bug

用户点 📍 之后"回到主界面"，根因是**引用上没有章号**（教程书的引用是我们自己造的，
`chapterNum` 是 undefined，`Number(undefined) || 0` = 0），深链缺了 `&chapter=`，
阅读器只能从头打开。更根本的是方向错了：点"跳到原文"要的是**让我看见那句话在哪**，
不是"把整本书重新打开一遍"。现在走同页定位（`readerCommand` 的 `locate`）：
在当前这一本里找那段原文、滚过去、圈一下，**不重载、不丢阅读位置**；找不到才退回按章打开。
