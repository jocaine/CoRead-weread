# CoRead 会意图：产品设计方案

> 状态：设计方案（PRD 级），未实现。核心机制与规则随设计推进定稿。
> 配套操作文档（直接喂给 LLM 的读写提示词素材）：[topic-library-ops.md](topic-library-ops.md)
> 用户情况与观念画像（总结式维护，不进头部）：[self-portrait-design.md](self-portrait-design.md)

## 1. 产品概述

CoRead 阅读助手的**讨论记忆层**。当前记忆按书隔离、只增不减；本产品改为**按知识点组织**：判专题化后的专题化讨论，收口时固化成一个**不可变的节点**（去聚合判同，2026-08-29 用户定调：每次固化都新建节点，同一个知识点被聊多次 = 多个节点，靠边连起来）；节点之间的**拓扑关系由用户自己的问题意识发展**——用户说"我想到我们之前说的『苏联的工业化史』，他和南美这里的工业化历史的有着不同的走向，为什么会有这样的不同的走向呢？"，系统记录一条从旧知识点到当前讨论的有向边。上下文历史的填充，按有向图从 root 到 recent 的路径组装。

一句话定位：会意图是**用户的知识点拓扑图**——节点是知识点（狭隘范畴），边是用户问题意识的轨迹。

## 2. 背景与问题

当前记忆策略是「按书隔离的全量历史」：每本书一段独立的对话历史，只增不减，每次提问把该书全部历史发给 LLM。

两个病根：

1. **跨书讨论被切碎**。真实案例：读《静静的顿河》第六章，从一段"老人认出故人"的划线聊出了「北欧福利国家的地基」「列宁工人贵族论」共 13 轮讨论，全被记在《静静的顿河》这一本书名下。换一本书再聊北欧，这些积累取不出来——书隔离把相关讨论按载体切碎了。
2. **token 无上限**。长度控制只在记忆固化环节生效，不作用于对话输入。阅读越久，请求越贵越慢，最终超出上下文窗口上限。

跨书检索此前有过一次雏形：只对已收束的结论做关键词匹配取回，因中文分词无法落地而整体禁用。

**为什么必须做**：短视频 / 算法推荐提供的是**碎片化知识点**——散乱、无关联、无主体，今天刷到明天忘。本产品从主体的困境出发，按"困境 → 问题意识 → 具体问题与知识点"组织：知识点是手段，问题意识是主线，主体是出发点。**问题意识属于用户**——系统不猜测用户追什么母题，而是让用户自己的引用（"我想到我们之前说的X"）把知识点连起来。

## 3. 目标

1. **用有向图替代机械的跨书联动**：旧方案对已收束结论做关键词匹配取回，因中文分词无法落地；图方案把知识点作为节点，用户引用作为边，换书重访同一知识点时整条路径自然带回。
2. **有界组装上下文，取代按书全量历史**：提问时按四层结构有界组装（本章标注 → 全书热点 → 图路径上下文 + 最近几轮），替换"整本书历史全量回灌"。路径组装有界靠**选择**（只取 root→recent 路径上的节点），不靠截断。

## 4. 功能设计：对话的上下文组装

本次改动：**优化对话的上下文组装**——由"整本书历史全量回灌"改为"按四层结构有界组装"。会意图（§5）是支撑机制。

### 4.1 用户提问时：组装上下文（读路径）

用户提问时，产品组装给模型的上下文 = 四层 + 系统指令：

```
[SYSTEM 指令]                  ← AGENT.md + profile + soul（不变；用户情况/观念走 self-portrait，不进头部）
[正在共读]《书名》章节
[本章标注讨论]                 ← L1：本章所有标注的问答线程
[全书重点标注(提问>n次)]        ← L2：全书热标注线程
[图路径上下文]                 ← L3：当前讨论节点沿有向图 root→recent 路径上的节点内容（机制见 §5）
[最近几轮]                     ← 小滚动窗口，承载自由提问的连贯性
用户提问: ...
```

各层规则：

- **L1 本章标注讨论**：范围 = 当前书、当前章节内全部标注及其问答线程；数据来源 = 现有记录按书+章节筛选；作用 = 立即的阅读对话记忆。
- **L2 全书热点标注**：范围 = 当前书全书中被提问次数 >n 的标注（n 初始 3）；数据来源 = 按选中文字统计，不引入新状态；作用 = 全书范围内用户真正在意的重点段落，跨章节带回。
- **L3 图路径上下文**：范围 = 跨书持久的知识点拓扑；数据来源 = 会意图（见 §5）；检索机制 = 引用解析（§5.4 ③）：用户发言中引用旧知识点（"我们之前说的X"）→ 命中节点 → 沿有向图取该节点的 root→recent 路径，路径上全部节点的内容（节点 point + 讨论）作为本会话后续上下文；**多引用取并集，不截断**；作用 = 跨书联动的深度记忆，拓扑由用户问题意识驱动。
- **滚动窗口**：小窗口（初始 6-8 轮）承载自由提问的连贯性（如"再展开说说泵和阀"）；L1/L2 已覆盖标注内讨论，窗口只处理自由消息。

**关键性质**：L1、L2 是纯查表（本章有哪些标注、哪些标注被提问 >n 次，都是确定数据，不需要语义判断）；L3 的语义判断只有一处——引用解析（用户发言里有没有引用、引用了哪个节点）。固化（§5.4 ②）发生在收口时，不进上下文组装。

## 5. 核心机制：会意图（有向图拓扑）

会意图是 L3"图路径上下文"（§4.1）的数据来源和支撑：它把用户追过的知识点从各本书的讨论里固化下来（每次收口讨论一个节点），节点之间的边由用户引用发展——让"换书再聊同一知识点"和"知识点之间的关联"都成为可能。

数据模型含三个对象，分属两层：**会意系统**（判断层）、**会意图**（存储层：节点 + 边）。画像层存于 profile.md（见 §6），不属会意图。

```
会意系统（判断层）        上下文 + 提示词（LLM 判断机制：判专题化、引用解析）
会意图（存储层）          有向图：节点（收口讨论的固化，不可变）+ 边（用户引用轨迹 + 段间衍生）
```

### 5.1 有向图结构：问题意识交还给用户

**节点** = 一次收口讨论组的固化（2026-08-29 用户定调：**去聚合判同，节点不可变**——每次固化都新建节点，建成后不并入、不追加、不改写；同一个知识点被聊多次 = 多个节点，靠边连起来）。节点之间没有系统预设的关系——**系统不判"哪个知识点追哪个母题"**。

**边** = 用户问题意识的轨迹。用户在讨论中主动引用旧知识点（"我想到我们之前说的X"），系统记录一条边：旧知识点 → 当前讨论所在节点。边的方向是**引用方向**（被引用的在前，当前的在后），整张图由此成为有向图；没有入边的节点是 root，最新讨论所在的节点是 recent。另有 derived 边（同一栈相邻段之间的对话连续性衍生，§5.4 ②）。

**问题意识交还给用户**：

- 系统的职责：判专题化（有没有可推进内核）、引用解析（用户引用了哪个节点）——都是**狭隘范畴**的判断，不涉及"母题"。固化只做派生（point / 能指）与新建节点，**不做聚合判同**（不猜"这属于哪个节点"——用户引用时自己说）。
- 用户的职责：用引用表达问题意识——"我想到我们之前说的X"，X 与当前讨论的关系由用户自己建立。
- 母题不再存储为字段。母题（如果存在）显现为图上的**汇聚结构**——多个节点被用户反复引用回来形成的形态；它是可观察的图结构，不是可存储的本质（见 §5.2 反向自检）。

### 5.2 会意系统（判断层）

LLM 判断机制，两个动作 + 一个观察：

- **① 判专题化**：判断一条讨论是否值得进会意图（有无可推进内核）。判定单元为讨论单元（栈），栈内另有判同一性（§5.4 ①）。多数讨论止于此。
- **② 固化（去聚合判同，2026-08-29 用户定调）**：收口的专题化讨论**直接新建节点**——不再判断"属于哪个已有知识点节点"（系统不猜：连"是不是同一个知识点"都不猜，等用户引用时自己说）。节点不可变：建成后不并入、不追加、不改写。
- **③ 引用解析**：用户发言中引用旧知识点时，找出指认旧知识点的说法并匹配节点。**一次发言可命中多个节点**，命中即取上下文（L3）并暂存；**建边在固化时**执行（当前讨论固化出节点后）；**不需要用户轻确认**（错边事后可删可改，§5.4 ③）。
- **④ 反向自检（观察）**：对图结构的观察——某节点长期无入边/无引用、图上的汇聚结构变化，提示读者的问题意识可能转移（观察结果只作提示，不做自动改写；具体机制待定）。

存储（上下文 + 提示词）：

- **上下文**：判断素材——读者画像（经历 / 困境 / 欲望，§6）、相关节点与讨论、当前会意的沉淀。节点 id 不存储，判断时从会意图读取。
- **提示词**：两个判断场景的指令——判专题化、引用解析。

更新：会意为稳定量。会话中不重算，固化时重检更新（动作④观察）。用户提问（讨论单元）用于判断（动作①），引用用于建边（动作③），均不参与上下文组装。由具体问题溯源、画像佐证而沉淀（见 §5.1 溯源）。

### 5.3 会意图（存储层）

会意图的存储：一张有向图，节点 + 边，跨书持久，是 L3"图路径上下文"（§4.1）的数据来源。文件级存储，一张图一个文件，便于读写与路径取用。

#### 节点 node

一个节点 = 一次收口讨论组的固化（节点不可变：建成后不并入、不追加、不改写，2026-08-29 用户定调）。

```json
{
  // 节点（会意图的 node）= 一次收口讨论组的固化，不可变；文件级存储
  // 注释规则：数组含义写在数组键行尾；结构体含义写在元素对象开头；其余为字段含义。
  "id": "n_nordic_position",        // 节点 id：slug，创建时由系统生成
  "point": "北欧福利模式的历史成因及其不可复制性", // 知识点表述：解释落点形态，一句话（派生，§5.4②）
  "aliases": [                      // 数组：能指（2026-08-29 定调）——被卸除的能指：捡回 point 卸下的背景内容
    "北欧福利靠外部流量还是内部制度",  //   重心在背景对象，陈述完整（读这条能把握该背景内容）；
    "泵和阀"                        //   只捡讨论里展开过的；数量不限；可手动改写；引用命中不记词
  ],
  "discussions": [                  // 数组：本节点的专题化讨论（节点不可变，恒 1 条）
    {
      // 元素结构体（discussion）：一次专题化讨论。字段含义：
      //   question      该次讨论追的具体问题，收口时归纳成一句（§5.4① / lib/thread-question.js）
      //   book / chapter  讨论发生在哪本书 / 哪个章节
      //   excerpts      交锋轮次原文（数组，见下）
      "question": "一种秩序/制度靠什么维持得下去？维持条件是内生的还是外来的？能被再生产吗？",
      "book": "《静静的顿河》",
      "chapter": "六",

      "excerpts": [                 // 数组：关键交锋轮次原文（固化时去寒暄/岔开，只留推进轮次，不设上限）
        {
          // 元素结构体：一轮交锋原文。字段含义：
          //   q  用户提问原文
          //   a  AI 回复原文
          //   t  轮次时间戳（毫秒）
          "q": "真正撑住北欧福利的不是技术是政治遗产…",
          "a": "你纠的这个点我认一半…",
          "t": 1786173499706
        }
      ]
    }
  ],

  "createdAt": 0,                   // 节点创建时间戳（毫秒，示例 0 为占位）
  "updatedAt": 0                    // 节点最近更新时间戳（毫秒，示例 0 为占位）
}
```

#### 边 edge

一条边 = 一次问题意识关联：要么是用户引用旧知识点（把当前讨论挂到旧知识点上），要么是对话连续性衍生（后一讨论从前一讨论思考中长出来，无显式引用也算）。

```json
{
  // 边（会意图的 edge）= 一次问题意识关联；有向：from = 被引用的旧知识点 / 被衍生的前一条讨论，
  //   to = 当前讨论所在节点
  // 2026-08-27 定调：去掉 quote 字段——追溯与删改触发均未实现，引用短语不落库
  // （不进 aliases、不存进边、不进解析协议——协议只返回命中 id）；衍生理由留在分割/收口的事件日志里。
  "from": "n_soviet_industrialization",   // 被引用的旧知识点节点 id
  "to": "n_south_america_industrialization", // 当前讨论所在节点 id（引用发生时该讨论固化出的节点）
  "kind": "user"                           // 边的来源：user（用户问题意识引用）或 derived（对话连续性衍生，分割/收口时判定，§5.4③）
}
```

#### 图的性质

- **有向**：边的来源有两种——user：用户发言里引用旧知识点（"我想到我们之前说的X"），引用解析命中后建边，**系统不猜引用**；derived：后一讨论从前一讨论的思考中衍生（追问、延伸、对比、联想，无显式引用句式也算），在分割/收口时判定并建边。方向 = 引用/衍生方向。
- **root**：没有入边的节点（最早被追的知识点）。
- **recent**：当前讨论所在节点。
- **多引用**：一次发言可命中多个节点 → 上下文取多条路径的**并集，不截断**（§5.4 ④）；多条 user 边在固化时一并建（§5.4 ③）。
- **可纠正**：错边事后可删（remove_edge）、可改（update_edge），按 from+to 定位（§5.4 ③）。

### 5.4 判断机制

会意系统的三个动作在此定稿：① 判专题化、② 固化（去聚合判同，2026-08-29 用户定调）、③ 引用解析。先看**总览流程**（一张图讲完一次讨论的完整生命线），再分动作看细节。

#### 总览流程

流程图统一约定（流程性图示适用）：`→` 前进，`├─`/`└─` 分支，缩进表示层级，`——` 注释。

一次讨论从提问到入库的完整生命线（会话中 + 固化时）：

```
用户提问（材料 = 提问本身；有划线时划线仅解析指代）
  → 判专题化（动作①：有无可推进内核）——多数讨论停在这里
      ├─ 专题化 → 进入讨论单元（栈）继续追（同一性判断见 §5.4①）
      └─ 不专题化 → 留在本会话讨论，不进会意图
  讨论中：用户发言引用旧知识点（"我想到我们之前说的X"）
      → 引用解析（动作③）命中节点 → 各命中节点的 root→recent 路径并入本会话后续上下文（L3）；
        引用挂消息（不建边——当前讨论尚未固化出节点）
  新专题化讨论到来 → 收口固化（2026-08-28 定调：收口即固化——新专题化讨论将旧的全体弹栈的
      那一刻，当场固化后分段：先判专题化、再判同一性，把栈内发散的具体问题细切成多个
      不可分割组 → 分割后每段归纳问题 → 固化（派生 point/能指 → 新建节点，节点不可变）
      → user 边；同栈相邻段间判定衍生 → derived 边 → 写图；关闭 / 启动恢复不做收口固化，
      只保存/恢复进行中的讨论）；画像补充（画像的补充时机，§5.5）
```

#### ① 判专题化与分割（固化后分割）

判专题化由会意系统执行（动作①），判据是内容：问题有无**可推进的问题内核**，与对话表象（交锋、回响等信号）无关：

- 有内核：问题是分析性的、关于机制/结构/关系的（"一种秩序靠什么维持"），能继续追问、可跨书应用。
- 无内核：一次性能答完的事实澄清（"这人物原型是谁"）、闲聊 → 不进会意图。

触发：**只有用户提问**。判定材料是提问本身——提问透露出用户真正追的问题；只有划线、没有提问不判：说明用户还没透出观点（可能只是标记重点、问历史背景或没读懂），没有观点可判。**有划线时，划线作为上下文附带，仅用于解析提问里的指代**（例："那这个怎么维持？"里的"这个"指划线里的什么）——指代解析后是机制问题的照常专题化；无划线可解析的指代短问保守不进；词义/闲聊/主观评价不因划线内容深刻而误判。

**收口固化（2026-08-28 用户定调）**：收口即固化——**新的专题化讨论将旧的全体弹栈的那一刻**，当场对弹出的旧讨论做**固化后分段**（lib/segment-stack.js：**先判专题化、再判同一性**——与实时栈分割（只做有限判断同一性，承接即同一）逻辑不同；无内核轮次**不做过滤处理**（不滤掉、不 ignored：它们不是知识点、不参与判同一，跟随并入当前组），把栈内发散开的具体问题细切成多个**不可分割**组）→ **分割之后**每段归纳问题 → **固化**（派生 point → 拾取被卸除的能指 → 新建节点；**节点不可变**——2026-08-29 用户定调：去聚合判同，不再判断"属于哪个已有节点"）→ user 边 → 段间 derived 边 → 写图。**关闭、启动恢复不做收口固化**：进行中的讨论留在栈里（topic_stack.json 跨会话持久化），讨论没被新专题化弹栈就不收口。

**栈状态机**（实时，逐条消息）：

```
空栈 + 消息 → 判专题化（可推进内核判据，入口过滤）
  ├─ 有内核 → 入栈（消息 + 划线 + AI 回复全带上）
  └─ 无内核 → 忽略，栈保持空（不会被切出来）
非空栈 + 消息 → 判同一性（与栈内累积内容比）
  ├─ 同一问题 → 入栈累积
  └─ 不同问题 → 判专题化
        ├─ 无内核 → 忽略（不入栈，不切断）
        └─ 有内核 → 收口固化：全部弹栈 → 固化后分段（先判专题化、再判同一性）
                     → 分割后每段归纳问题 → 固化（派生 → 新建节点，节点不可变）→ user 边
                     → 同栈相邻段间判定衍生 → derived 边 → 写图
```

**按书隔离**：栈按 bookKey 分组（bookKey = baseBookId | '_common'），**换书即换栈**——新书的讨论从空栈重新判专题化，旧书栈保持原位待回访；同一本书内换对象/换角度仍不切断。

##### 降级判定：AI 回复成种子（判专题化的补考）

判专题化第一判的判定材料只有提问本身（+划线解析指代），纯净不受外部上下文影响。第一判判为"非专题化"时，若对话流里存在上一轮 AI 回复，自动降级把该回复作为辅助材料补考一次——提问自身看不出内核，可能只是信息不足：例"人生有什么意义"被忽略后，AI 回复抛出"意义是主观构建的"这个可辩观点，用户顺着追问"那照这么说呢？"，"你这么说"这个指代要上一轮 AI 回复才能解析。

降级判定的边界（钉死，防带偏）：
- 仅当这条消息在语义上承接上一轮 AI 回复（针对它追问、反驳、展开、质疑）时，AI 回复才作为判定材料参与：评估「提问 + AI 回复」合起来是否有可推进内核 → 有则专题化，无则不专题化。
- 不承接（全新话题、与上一轮 AI 回复无关）→ 维持非专题化。
- 纯反应（"嗯嗯""确实""明白了"）不构成承接 → 维持非专题化。
- AI 回复自身深刻不是判据——必须这条消息承接了它才参与判定。与"划线内容深刻不判专题化"同一哲学：划线没有"承接"这个动作，所以划线仅解析指代；AI 回复参与的前提正是"用户承接"。

上一轮 AI 回复经 assistantContext 字段传入判专题化，结构为 { content, selected? }。content 为回复文本，selected 为这条 AI 回复针对的划线（划线结构体 { text, book, chapter }）。降级判定的判定材料只用 content；selected 不参与判据。

降级判专题化（usedAssist）→ 入段时**补入上一轮 AI 回复作背景轮次**：{ role: 'assistant', content, selected? }，selected 为它针对的划线。它是这场讨论的真正起点，缺了它后续同一性判断材料不完整。

适用边界：降级只在**空段判专题化入口**启用。非空段"换问题 → 判专题化"分支不带 AI 回复做降级——段内已有当前讨论上下文，而"上一轮 AI 回复"属于被换掉的旧问题，新消息不承接它，降级只会误判。

##### 三个判断的职责

- 判专题化：一条消息有没有可推进内核。同一判据，两个用法——空段开段（第一判纯净，必要时降级补考）、非空段"换问题"分支（不带 AI 回复，不降级）。
- 判同一性：新消息与当前段累积内容是不是同一个问题。二元等价判断，只判"是不是同一个"，不命名、不归类。识别接续不靠显式指代——用户对上一轮答复给出新观点、反驳或理解延伸（"不对，我觉得制度自身的惯性才是关键"）即使没有"那/这/它"，只要承接上一轮内容就是同一问题。
- 收口（切段）：没有独立的"讨论结束"判断。消息不换问题就一直留在当前段；换问题且有内核才收口。收口动作把整段打包为专题化讨论组 { ts, entries }，ts 取收口时间，entries 为段内全部轮次。

##### 边界规则

- **判定顺序钉死：先判专题化（入口过滤），有内核再判同一性**。无内核的消息直接忽略——**不会被切出来**；同一性只作用于有内核的消息之间。同一性优先于切段——一条消息只要承接当前问题（同一），就入段累积，**不再判它是否专题化**（例："再展开说说泵和阀""为什么？"单独看无内核，但承接当前讨论，入段——注意这里"无内核"是判专题化的结果，不是消息的先验属性，它必须先过判专题化入口才有资格谈承接）；只有被判为**非同一**的消息，才切段。
- 角度切换不切断：同一问题换对象、换角度，是推进，不是新讨论（换书由分组切断——消息流按 bookKey 分组；同一知识点的跨书延续由引用解析建边衔接，§5.4 ③）。
- 问题意识转移才切断：用户追的问题本身换了（不再是同一个问题）。
- 用户解绑（取消引用转自由对话）：内容偏离原划线，不代表讨论结束，不切断。
- 非同一且无内核的消息（穿插的闲聊、事实澄清、新话题寒暄）：忽略（不入段、不切断）。产品上正常回答，只是不累积进会意图。
- **跨会话承接**：消息流跨会话连续追加，下一次固化时整体分割——承接同一问题的消息（判同一性）自然合成一段，不需要栈跨会话持久化。

##### 入段 ≠ 固化节点

入段只是初判（可推进内核判据过即可），不等于固化。固化（§5.4 ②）在收口分段后执行：每段派生 point/能指 → **新建节点**（节点不可变，不做聚合判同）。

##### 段内容与上下文

段条目 = { role, content, selected? }。role 为 user 或 assistant；content 为发言文本；selected 为划线结构体 { text, book, chapter }（可缺省）。user 轮次带自己的划线；assistant 轮次带它针对的划线。段内累积内容作为同一性判断的上下文。长讨论需控制上下文量（窗口化/摘要，细则另定）。

#### ② 固化：专题化讨论 → 新建节点（去聚合判同，2026-08-29 用户定调）

> **术语（2026-08-28 澄清；2026-08-29 废除聚合判同）**：原"聚合（动作②）"指"聚合判同"这一局限步骤——判断讨论属于哪个已有节点，还是新建。**2026-08-29 用户定调：去掉聚合判同**——系统不再判断"这条讨论属于哪个已有知识点节点"（系统不猜：连"是不是同一个知识点"都不猜，等用户引用时自己说）。固化 = 派生 point → 拾取被卸除的能指 → 新建节点 → user 边 → derived 边 → 写图。

收口的专题化讨论（讨论组 { ts, entries }）分段后，每段**直接新建节点**：

- **新建节点**：派生 point（解释落点形态）+ 拾取被卸除的能指（aliases，重心在背景对象）→ 建节点（discussions 入库，excerpts 无损）。
- **节点不可变**：建成后不并入、不追加、不改写（手动修正走 update_node_point / update_node_aliases）。**同一个知识点被聊多次 = 多个节点**，靠用户引用（user 边）与同栈段间衍生（derived 边）连起来。
- **宁漏勿误**：无引用就孤立——漏了无痛（用户以后引用时自己连上）；**不再有"把两个知识点混进一个节点"的污染风险**（节点永不合并）。
- 固化发生在**收口时**（2026-08-28 定调：收口即固化——新专题化讨论弹栈旧讨论的那一刻当场固化；关闭/启动恢复不做），不进上下文组装。

#### ③ 引用解析：用户问题意识 → 边

用户发言中引用旧知识点（"我想到我们之前说的X""前面聊过的Y""上次那个Z"），会意系统找出指认旧知识点的说法并匹配节点：

- **命中与建边解耦（2026-08-27 定调）**：会话中命中只做一件事——把各命中节点的 root→recent 路径并集并入本会话后续上下文（L3，§5.4 ④），**不建边**（此刻当前讨论尚未收口固化出节点，to 节点不存在，会话也不需要边）；引用先暂存（**挂在触发引用的消息条目上**，随栈持久化，2026-08-28 定调）。**收口固化时**该讨论固化出节点后，收集组内消息挂的引用建边（源节点 → 触发回合所属节点；同 pair 去重）。建边时机不与命中同时发生。

- **LLM 介入（2026-08-27 定调：去掉字符串粗召回与覆盖判定，纯语义判定一次完成；材料只放条目身份，不放讨论原文；2026-08-29 加强：语义匹配，能指词面命中不是必要条件，内容线索是底线——空指不解析，不惯着用户）**：对**全量节点**做精判断（匹配依据：node.point、**node.aliases（被卸除的能指）**、节点内讨论过的问题；允许同义、简称、换表述、话题描述）。**内容线索是底线**：说法必须透露指认的是哪个知识点的信息——能指词、话题词、对讨论内容的描述；纯指示代词（"上次那个""那个问题"）或纯时间指代（"就和我们上次聊的一样"）没透露任何线索 → 不解析、不匹配。**指认意图**：只是恰好提到相关词、没有指认意图的，不是引用（讨论原文里偶然出现的词不算数——不是引用，是过滤，宁漏勿误）。多引用漏判**静默接受**（宁漏勿误：漏了无痛，用户以后会再引用）；只有输出非法（非 JSON/协议不符）才重试。
- **一次发言可命中多个节点**：全部命中 → 上下文取各节点路径并集；收口固化时按触发回合所属节点全部建边（多引用 → 多条边）。
- **不需要轻确认**：命中即取上下文、暂存引用，不打断用户（"不用问，直接记"）。
- **命中不记词**：引用短语**不落库**——不进 aliases、不存进边、不进解析协议（协议只返回命中节点 id 列表）；aliases 是能指，节点创建时拾取，不随引用行为增长（2026-08-29 定调：aliases = 被卸除的能指，替代旧的"备选标题"；同日定调：追溯/删改触发未实现，edge 暂不落 quote 字段）。
- **未命中**：不取上下文、不暂存引用（用户可能记错或节点尚未建立；引用留在对话里，不强迫处理）。
- **错边事后可纠正**：remove_edge（删）、update_edge（改），按 from+to 定位（同 pair 多条边全部删/改；精确到单条的核对机制待追溯落地后另定）。
- 引用解析触发时机：**会话中**（用户发言时）——命中节点 → 各命中节点的 root→recent 路径并集并入本会话后续上下文（L3），引用**挂消息条目**（随栈持久化）；**建边在收口固化时**（该讨论固化出节点，源节点 → 触发回合所属节点）。

**能指（aliases）的生成（2026-08-29 定调：捡回被卸除的能指）**：point 抓住落点，讨论中作为已知背景被带出的对象及其展开内容在 point 里退场——aliases 把它们**捡回来**，留在节点上为能指链的漂移**保留接驳材料**（系统不预设漂移方向；用户以后从这些对象滑向新话题时，节点能被命中）。节点创建时（固化直建）由 LLM 从 point + **全量讨论内容（不截取）**拾取：**重心在背景对象，不在落点**（不是 point 的换表述，重心与 point 对称）；每条把该背景内容说清楚（陈述完整，读这一条能把握这条内容，不许压缩成看不出内容的短提法）；只捡讨论里实际展开过的背景内容（不造面：不许发明讨论里没有的对象或角度、说法必须来自讨论本身）；覆盖展开过的背景面（合起来不丢面）；**数量不限**；可手动改写（update 入口与 point 同级）。

**derived 边（对话连续性，2026-08-28 定调：只存在于固化后的分段逻辑中）**：同一栈内的对话必然有思维关系（实时栈分割只做有限判断同一性，栈内是思维连续的段，但具体问题可能发散）——收口弹栈后分段切出的**同一栈内相邻段**之间判定衍生（后一段是否从前一段的思考中衍生，追问/延伸/对比/联想，无显式引用句式也算）；**不比对上一个收口专题讨论**（不同栈之间不判定衍生）。宁漏勿误：拿不准不建边（漏了无痛，用户以后显式引用时补上；错了污染拓扑）。衍生理由留在事件日志里，不存进边。

#### ④ 上下文填充：root → recent 路径并集

L3"图路径上下文"的组装规则（§4.1）：

- **基本路径**：从目标节点的 root（沿入边反向走到无入边的节点）到目标节点（recent），路径上所有节点。
- **多引用**：一次发言命中多个节点 → 各节点取自己的 root→recent 路径 → **并集**（去重）。
- **不截断**：路径上节点的内容（node.point + 全部 discussions 的 excerpts 全文）全量进入，不截断。（上下文有界靠选择——只取路径上的节点，不靠截断。）
- **未引用**：无命中时，不进 L3（用户没把当前讨论挂到任何旧知识点上）；当前讨论的内容由栈（§5.4①）承载。
- **排序**：按图拓扑序（root 在前，recent 在后）输出。

### 5.5 生命周期与维护

判专题化在会话中（用户提问时）；固化（动作②）在**收口时**（收口即固化——派生 point/能指 → 新建节点，不做聚合判同）；引用解析在会话中（用户发言时）。建图、固化、推进均由上述机制完成。

**三类决策时机**：

- **会话中（用户提问时）**：会意系统判专题化（可推进内核判据 + 讨论单元定栈范围，动作①）→ 用户发言引用旧知识点时执行引用解析（动作③），命中节点 → 各命中节点的 root→recent 路径并集并入本会话后续上下文（L3），引用**挂消息条目**、**不建边**。用户谈到自己的情况/观念时维护画像（[self-portrait-design.md](self-portrait-design.md)；总结式追加，不进 profile，保持头部前缀稳定）。
- **收口时（收口固化，2026-08-28 用户定调）**：**新的专题化讨论将旧的全体弹栈的那一刻** → 固化后分段（先判专题化、再判同一性，细切发散的具体问题）→ **分割之后**每段归纳问题 → **固化**（派生 point → 拾取被卸除的能指 → 新建节点〔节点不可变，不做聚合判同〕）→ user 边（段内消息挂的引用按触发回合归属）→ 同栈相邻段间判定衍生 → derived 边 → 写图文件；单段失败弃段记日志（宁漏勿误）。
- **关闭 / 启动恢复**：**不做收口固化**——进行中的讨论留在栈里（topic_stack.json 跨会话持久化），讨论没被新专题化弹栈就不收口；启动时恢复栈 + 每本书上一轮 AI 回复（判专题化降级判定材料）。

**漏斗总纲**：

```
讨论 → 会意图：判专题化（可推进内核）→ 收口固化（新专题化弹栈旧讨论：固化后分段 → 每段归纳问题 → 固化（派生 → 新建节点，节点不可变）→ user 边 → 同栈段间衍生 → derived 边）
引用 → 会意图：引用解析（会话中命中：取上下文 + 引用挂消息）→ 收口固化时建边（源节点 → 触发回合所属节点）
```

判定标准自下而上收紧：知识点须能持续追问、跨书推进，一次好奇不够；user 引用边的建立只认用户自己的引用，系统不猜；derived 边只在分割/收口时判定对话连续性（§5.4③），宁漏勿误。

**画像的补充时机**

- 用户谈到自己的情况（家庭/工作/年龄/处境）或表露观念（立场/价值观/看问题的方式）→ 会话中即时总结进 **self-portrait**（[self-portrait-design.md](self-portrait-design.md)），画像语言陈述、不抄原话，不进 profile（头部前缀稳定，LLM 缓存命中率不受影响）。
- 推出来的（观察：反复在"制度的可复制性"上纠正我 → 可能反感宿命论）→ 本版不处理（日记只记用户说出口的；推断类内容留待后续设计）。

**维护操作**（产品层只规定有哪些操作，不规定提示词细节）：

- `create_node(point, discussion, aliases?)` — 新建节点（固化直建）：以讨论的问题归纳出 point（解释落点形态），并拾取被卸除的能指（aliases，重心在背景对象，§5.4③），建节点。**节点不可变**——建成后不并入、不追加、不改写（2026-08-29 用户定调：去聚合判同）。
- `add_edge(from, to, kind?)` — 建边：kind = user（引用解析命中后，记录用户的问题意识引用）或 derived（分割/收口时判定对话连续性）。
- `remove_edge(from, to)` / `update_edge(from, to, new_from?, new_to?)` — 删边 / 改边：错边纠正，按 from+to 定位（同 pair 多条边全部删/改）。
- `update_node_point(node_id, point)` / `update_node_aliases(node_id, aliases)` — 改 point / 改能指：用户审阅时手动修正（固化后节点不被系统修改，改写走这两个入口）。
- `context_path(node_id)` — 取图路径上下文：root→recent 路径并集（不截断），供 L3 组装。

维护时如何写 point、如何抽取引用——这些是直接喂给 LLM 的提示词素材，见操作文档 [topic-library-ops.md](topic-library-ops.md)。

## 6. 与现有记忆体系的边界

- profile.md = 用户的深层画像（身份、环境、成长、抱负 + 阅读品味）——不变，作为会意系统的佐证输入；用户自述不再进 profile。
- self-portrait = 用户情况与观念画像——新增；总结式维护（有新信息才追加条目，去重靠比对现有画像），不进头部上下文；区别于 profile 的合并式重写。
- soul.md = 你自己的立场与相处方式——不变。
- **会意图 = 讨论内容本身**（中间保真度），补上 profile/soul（高损蒸馏）和 journal（不可查询）之间的空档。

## 7. 前端可视化：会意图拓扑视图

> 状态：已实现（extension/graph-view.js，AI-020）。协议与实现随使用演进。

### 7.1 产品形态

侧栏「◎」按钮打开**全面板图视图**（Obsidian 式）：节点 = 知识点（point），边 = 用户问题意识轨迹（有向：user 引用 / derived 衍生）。两种状态：

- **观察态（一般情况）**：浏览整张拓扑图——滚轮缩放、拖拽空白平移、拖节点微调布局、悬停高亮邻接子图、点选节点看详情（point / 能指 / 节点讨论 / 元信息）、搜索定位（point / 能指 / 讨论问题）、图例（边种类、root、recent）。真实图为空时提供「载入演示拓扑」预览交互。
- **命中态（对话命中）**：会话中引用解析（动作③）命中旧知识点 → 高亮各命中节点的 **root→recent 路径并集**（与 L3 取数同规则，§5.4④）：路径节点与路径边提亮为强调色，其余元素压暗；命中节点（recent）脉冲标记，root 节点虚线环；顶部横幅说明命中来源（节点数 / 引用原因），可一键清除。图未打开时命中先暂存并 toast 提示，打开即应用。

### 7.2 数据流与协议

- **图数据**：`GET /graph`（receiver）读 `agent/data/knowledge-graph.json`（会意系统固化产物：一张图一个文件，§5.3；文件不存在 → 空图）；图文件 mtime 变化 → SSE `graph-updated`，图视图开着自动重拉（重拉保留高亮，按 targets 重算）。`?demo=1` 返回演示拓扑（从 scripts/data/knowledge-graph-demo.json 的 events/demoOnly 重建），仅用于预览。
- **命中事件**：agent 引用解析命中后向 chat_output.jsonl 写一行 `{"role":"graph-hit","hits":["n_xx",...],"reason":"…"}`（不落 _stream、不渲染为消息气泡，/history 过滤）；receiver 按既有通道转发为 SSE message；侧栏收到后计算路径并高亮。**路径计算在客户端做**（与 contextOf 同规则：入边反向可达并集 + 拓扑序），服务端协议只传命中 id 列表——图视图不依赖 agent 侧是否已实现建边，只要命中协议成立即可高亮。
- **实现载体**：extension/graph-view.js（自包含、无依赖、Canvas 力导向布局）+ sidebar.html 遮罩容器与样式 + receiver /graph 端点（graph-data.js 读取层）。

### 7.3 边界

- 图视图只读不改：不提供节点/边的增删改入口（维护操作仍走 §5.5 的产品层入口）。
- 命中事件与建边解耦（沿用 §5.4③ 定调）：图视图的命中高亮不参与建边，只是 L3 取数的可视化回显。
- 演示拓扑与真实图互斥：载入演示后图视图标记「演示数据」，不污染真实图文件。
