# CoRead 话题库：产品设计方案

> 状态：设计方案（PRD 级），未实现。核心机制与规则随设计推进定稿。
> 配套操作文档（直接喂给 LLM 的读写提示词素材）：[topic-library-ops.md](topic-library-ops.md)

## 1. 产品概述

CoRead 阅读助手的**讨论记忆层**。当前记忆按书隔离、只增不减；本产品改为**按问题组织**：讨论内容按用户正在追的问题聚合成话题。跨书联动无需额外检索层——按问题意识组织话题后，换书再聊同一问题时，整条问题线索自然带回来。

一句话定位：话题库是**用户正在追的问题库**。

面向人群：主动阅读、有成体系求知需求的有志读者。

## 2. 背景与问题

当前记忆策略是「按书隔离的全量历史」：每本书一段独立的对话历史，只增不减，每次提问把该书全部历史发给 LLM。

两个病根：

1. **跨书讨论被切碎**。真实案例：读《静静的顿河》第六章，从一段"老人认出故人"的划线聊出了「北欧福利国家的地基」「列宁工人贵族论」共 13 轮讨论，全被记在《静静的顿河》这一本书名下。换一本书再聊北欧，这些积累取不出来——书隔离把相关讨论按载体切碎了。
2. **token 无上限**。长度控制只在记忆固化环节生效，不作用于对话输入。阅读越久，请求越贵越慢，最终超出上下文窗口上限。

跨书检索此前有过一次雏形：只对已收束的结论做关键词匹配取回，因中文分词无法落地而整体禁用。

**为什么必须做**：短视频 / 算法推荐提供的是**碎片化知识点**——散乱、无关联、无主体，今天刷到明天忘。本产品从主体的困境出发，按"困境 → 问题意识 → 具体问题与知识点"组织：知识点是手段，问题意识是主线，主体是出发点。

## 3. 目标

1. **用话题替代机械的跨书联动**：旧方案对已收束结论做关键词匹配取回，因中文分词无法落地；话题方案按问题意识组织，换书重访同一问题时整条线索自然带回。
2. **有界组装上下文，取代按书全量历史**：提问时按三层结构有界组装（本章标注 → 全书热点 → 相关话题 + 最近几轮），替换"整本书历史全量回灌"。每次请求更省、更准。

## 4. 功能设计：对话的上下文组装

本次改动：**优化对话的上下文组装**——由"整本书历史全量回灌"改为"按三层结构有界组装"。话题库（§5）是支撑机制。

### 4.1 用户提问时：组装上下文（读路径）

用户提问时，产品组装给模型的上下文 = 三层 + 系统指令：

```
[SYSTEM 指令]                  ← AGENT.md + profile + soul（不变）
[正在共读]《书名》章节
[本章标注讨论]                 ← L1：本章所有标注的问答线程
[全书重点标注(提问>n次)]        ← L2：全书热标注线程
[相关话题]                     ← L3：勾住的话题正文（机制见 §5）
[最近几轮]                     ← 小滚动窗口，承载自由提问的连贯性
用户提问: ...
```

各层规则：

- **L1 本章标注讨论**：范围 = 当前书、当前章节内全部标注及其问答线程；数据来源 = 现有记录按书+章节筛选；作用 = 立即的阅读对话记忆。
- **L2 全书热点标注**：范围 = 当前书全书中被提问次数 >n 的标注（n 初始 3）；数据来源 = 按选中文字统计，不引入新状态；作用 = 全书范围内用户真正在意的重点段落，跨章节带回。
- **L3 相关话题库**：范围 = 跨书持久的问题意识线索；数据来源 = 话题库（见 §5）；检索机制 = 会意系统判挂钩（见 §5.3 归类挂钩）：讨论专题化后判断它追的母题，勾住则取该话题的 question + 全部 threads 作为本会话后续上下文；作用 = 跨书联动的深度记忆。
- **滚动窗口**：小窗口（初始 6-8 轮）承载自由提问的连贯性（如"再展开说说泵和阀"）；L1/L2 已覆盖标注内讨论，窗口只处理自由消息。

**关键性质**：L1、L2 是纯查表（本章有哪些标注、哪些标注被提问 >n 次，都是确定数据，不需要语义判断）；只有 L3（选哪些话题）需要语义匹配——由会意系统判挂钩完成。

## 5. 核心机制：话题库

话题库是 L3"相关话题"（§4.1）的数据来源和支撑：它把用户追的问题从各本书的讨论里抽出来，聚合成一条条可跨书推进的问题线索，让"换书再聊同一问题"成为可能。

### 5.1 三层结构：问题意识驱动数据落位

三层共用同一套数据，按两个方向运行：

```
深层心理画像（profile）        身份 / 生活环境 / 成长经历 / 理想抱负 / 阅读品味——慢变量，佐证材料
    ↓ 佐证
会意系统（一套机制）            上下文 + 提示词；四个判断：判专题化、归类挂钩、派生母题、反向自检；不进上下文组装
    ↓ 派生母题 / 归类
话题层 topics（很多）           具体问题——操作层；每条含 motif（根源性母题）+ question（当前问题的具体化）
```

- **自上而下（阅读方向）——归类**：新讨论归入哪条话题，由会意系统判定。例：谈"北欧福利制度"与谈"社会主义土地改革"表面不同，同属"秩序/制度如何被制造与维持"这一母题，归入同一话题。归类依据是话题的**母题**（topic.motif，新建时由会意系统决定）；判断细节见 §5.3 归类挂钩。
- **自下而上（沉淀方向）——溯源**：阅读中遇到认知之外 → 好奇/不解 → 提出具体问题，落于话题层。话题反复推进后指向问题意识：用户为何这样发问——连着最近的生活困境与长久的成长经历。沿问题意识，以画像（明说的身份、经历、抱负）佐证，LLM 会意出"读者想从阅读中得到什么答案"（经历 + 困境 + 欲望），沉淀为会意系统的上下文（数据模型见 §5.2）。这是 §5.3 反向自检的依据。

**三层交互规则**：

- 阅读时：认知外 → 具体问题落于话题层，随各本书持续推进。阅读只更新话题层，不动会意系统。
- 沉淀时：具体问题溯源 + 画像佐证 → 会意系统。会意系统从具体问题归纳而来，沉淀为上下文 + 提示词；不设用户识别确认环节。
- 归类时（会话中，用户提问）：会意系统判专题化（入口，动作①，判定材料 = 提问本身；有划线时划线仅用于解析提问中的指代）→ 判挂钩（动作②）。勾住已有母题 → 该话题的 question + 全部 threads 接进本会话后续上下文；勾不住但专题化 → 新话题候选（收口进待归类桶）。判断细节见 §5.3 判专题化 / 归类挂钩。
- profile 是慢变量，不参与日常对话，仅作为会意系统的佐证材料（见 §5.3 画像的补充时机）；会意系统仅在话题结构变化时重检（见 §5.3 反向自检）。

**画像的定位（克制）**：用分析师观察技巧充实画像（怎么读、在哪交锋、反复绕回什么 → 背景与动机），服务于维护会意系统。不做创伤挖掘、不面质、不建独立心理档案；只在有信号时补充，区分"明说的"与"推出来的"，不把推断当事实。

### 5.2 数据模型

话题库含四个对象，分属两层：会意系统（判断层）、话题层（操作层）。画像层存于 profile.md（见 §6），不属话题库。

```
会意系统（判断层）        上下文 + 提示词（LLM 判断机制）
话题层（操作层）          话题库层（容器）、话题条目（item）、待归类桶（暂存）
```

**会意系统**：LLM 判断机制，理解读者"真正关心什么"。由读者的经历与困境、长期追问的欲望归纳而成，抽象度须覆盖不同书共同讨论的话题。长期攒下来的东西——欲望不靠明说，靠读者反复绕回的模式暴露，攒得越久越准（也越容易固化，故靠反向自检纠偏，见 §5.3 反向自检）。

存储（上下文 + 提示词）：

- **上下文**：判断素材——读者画像（经历 / 困境 / 欲望）、相关话题与讨论、当前会意的沉淀。话题 id 不存储，判断时从话题库读取。
- **提示词**：四个判断场景的指令——判专题化、归类挂钩、派生母题、反向自检。

判断（四个动作）：

- **① 判专题化**：判断一条讨论是否值得进话题库（有无可推进内核）。多数讨论止于此（§5.3 判专题化）。
- **② 归类挂钩**：判断专题化讨论追哪个母题——归入已有话题，或路由为新话题候选（§5.3 归类挂钩）。
- **③ 派生母题**：新话题转正时，按会意抽象层级生成 topic.motif（§5.3 归类挂钩 转正）。
- **④ 反向自检**：重检会意与结构是否贴合；不再贴合时，以老朋友式定向问取得读者真话为底，重新表述会意、更新上下文与提示词（§5.3 反向自检）。

母题（如"什么是正义"）是动作③的产物，写入话题层 topic.motif；会意系统只存产生母题的上下文与指令，不含母题本身。

更新：会意为稳定量。会话中不重算，固化时重检更新（动作④：结构变化或漂移疑似触发，漂移问答取得真话为重新表述之底）；用户提问（讨论单元）用于判断（动作①②），不参与上下文组装。由具体问题溯源、画像佐证而沉淀（见 §5.1 溯源）。

**话题库（话题层）**：话题层的存储，把用户追的问题按话题聚合为条目，跨书持久，是 L3"相关话题"（§4.1）的数据来源。含两类对象：**话题条目**（已转正，参与组装）、**待归类桶**（未转正草案，不进组装）。L3 组装时，会意系统判断"勾住哪些话题"，取该话题的 question + 全部 threads 为正文；会意系统与待归类桶不进上下文。

**话题条目（话题库的 item）**：一个话题 = 用户正在追的一条问题意识，与书解耦，靠多本书的阅读持续推进。文件级存储，一个话题一个条目，便于读写与挂钩取用。

```json
{
  "id": "t_what_sustains_order",
  "motif": "对权力与秩序如何被制造、维持，以及在其中的人如何被结构决定",
  "question": "一种秩序/制度靠什么维持得下去？维持条件是内生的还是外来的？能被再生产吗？",
  "progress": "从'技术霸权'假说 → 经'政治遗产'交锋 → 收敛到'结构性位置×制度化互为条件'；现判'制度是外部条件的函数，问供血何时断'",
  "threads": [
    {
      "book": "《静静的顿河》", "chapter": "六",
      "trigger": "划线'老人认出故人'",
      "contribution": "用户立场在此交锋中成型：制度优越性是幻觉，一切制度依附外部位置；但'不可再生产'判词本身也受质疑",
      "excerpts": [
        { "q": "真正撑住北欧福利的不是技术是政治遗产…", "a": "你纠的这个点我认一半…", "t": 1786173499706 }
      ]
    }
  ],
  "staleCount": 0,
  "createdAt": 0, "updatedAt": 0
}
```

字段说明：

- `id`：slug，创建时由 LLM 生成或系统生成（待定）。
- `motif`：根源性母题。新建话题时由会意系统决定"这个话题在追什么"，比 question 抽象一层（question 是母题在当前讨论里的具体化）。归类的依据。
- `question`：用户正在追的问题意识，一句话说清。话题存在的原因，也是判挂钩（§5.3 归类挂钩）的比对对象。
- `progress`：问题当前推进到的位置（现状一句），随讨论演进。供话题列表、检索与归档评估，不进 L3 上下文。
- `threads`：每本书对这条问题的一次推进——trigger（书侧触发点：划线 / 场景 / 自由提问，一句话）、contribution（这本书把问题推到了哪、用户立场如何转变，交锋留下的未决质疑一并写在这里）、excerpts（全部关键交锋轮次原文：固化时去掉寒暄/岔开，留下推进问题的轮次，不设数量上限）。L3 正文 = question + 全部 threads，选中的 thread 全文进入、不截断。
- `staleCount`：长期未触及，达到阈值后归档/降权。

（正文有界靠选择，不靠截断：只喂勾住的那条话题，其 threads 与 excerpts 全量进入。膨胀由待归类桶过滤与归档约束。）

**待归类桶 pending**：已收口、未转正的专题化讨论暂存区，不进 L3 上下文。栈收口时，勾不住已有母题的讨论入桶（勾住的直接归入已有话题，不经过这里）。桶条目 = 专题化讨论组 { ts, entries }：ts 为收口时间，entries 为整栈桶（全部推进轮次原文，含划线结构体）。转正要过系统复核：确认栈内有实质推进轮次且问题有可推进内核，才转正进话题库并派生母题。复核时机 = 收口后观察推进、证据充分时（挂钩/派生母题延迟，见 讨论单元（栈）），不靠未来回响信号。防止一次性好奇进入话题库（见 §5.3 归类挂钩）。

### 5.3 生命周期（维护）

建话题、归入、合并、推进均由会意机制完成。判专题化与挂钩在会话中（用户提问时）；建草稿、推进、会意重检在固化时后台完成（非交互式 tool loop）。

流程图统一约定（流程性图示适用）：`→` 前进，`├─`/`└─` 分支，缩进表示层级，`——` 注释。

**两类决策时机**：

- **会话中（用户提问时）**：会意系统判专题化（可推进内核判据 + 讨论单元定栈范围，动作①；判定材料 = 讨论单元，划线仅用于解析指代）→ 专题化的讨论进入判挂钩（归类挂钩，动作②）。挂钩的目的是**当场接上下文**：勾住已有母题，该话题的 question + 全部 threads 接进本会话后续上下文（L3）。用户明说的画像事实即时记（画像的补充时机）。漂移疑似时，后续回复中老朋友式直接问读者（反向自检的定向问步骤）。
- **会话固化（会话结束 / 启动恢复）**：顺序执行——画像补充（画像的补充时机）→ 挂钩落地：推进已有话题、复核待归类桶（收口后的讨论在观察推进后转正/归入，归类挂钩）→（若话题结构变化或漂移疑似）会意系统重检（反向自检）。

**画像的补充时机**

- 明说的（"我在基层工作过"）→ 会话中即时记，高置信。
- 推出来的（观察：反复在"制度的可复制性"上纠正我 → 可能反感宿命论）→ 固化时，信号门控：只有真暴露了背景 / 动机才写，标注为推断，没信号就跳过。
- 画像维度是慢变量，不每个会话重写，只在有信号时追加 / 修正。

**判专题化**

判专题化由会意系统执行（动作①），判据是内容：问题有无**可推进的问题内核**，与对话表象（交锋、回响等信号）无关：

- 有内核：问题是分析性的、关于机制/结构/关系的（"一种秩序靠什么维持"），能继续追问、可跨书应用。
- 无内核：一次性能答完的事实澄清（"这人物原型是谁"）、闲聊 → 不进话题库。

触发：**只有用户提问**。判定材料是提问本身——提问透露出用户真正追的问题；只有划线、没有提问不判：说明用户还没透出观点（可能只是标记重点、问历史背景或没读懂），没有观点可判。**有划线时，划线作为上下文附带，仅用于解析提问里的指代**（例："那这个怎么维持？"里的"这个"指划线里的什么）——指代解析后是机制问题的照常专题化；无划线可解析的指代短问保守不进（2026-08-11 定调，真实 API 冒烟 35 用例 × 3 轮 = 105/105 零摇摆验证：划线解析指代"该进就进"，词义/闲聊/主观评价不因划线内容深刻而误判）。空栈时按此判据判断一次（第一判纯净；判非专题化且有上一轮 AI 回复时走降级判定补考一次），入栈；后续轮次走栈模型的同一性判断，多数讨论止于此；只有专题化的讨论进入判挂钩（归类挂钩）。

**讨论单元（栈）**

判专题化的单元不是单次提问，而是一段连续追同一问题的沟通。范围由栈管理：栈 = 进行中的专题化讨论，跨会话持久化，重启/换会话不弹空（用户可能下次接着聊）。

**栈状态机**

```
空栈 + 消息 → 判专题化（可推进内核判据）
  ├─ 有内核 → 入栈（消息 + 划线 + AI 回复全带上）
  └─ 无内核 → 忽略，栈保持空
非空栈 + 消息 → 判同一性（与栈内累积内容比）
  ├─ 同一问题 → 入栈累积
  └─ 不同问题 → 判专题化
        ├─ 无内核 → 忽略（不入栈，不切断）
        └─ 有内核 → 收口：全部弹栈归档为一次专题化讨论 → 新消息开新栈
```

**降级判定：AI 回复成种子（空栈初判的补考，2026-08-11 定调）**

空栈 + 消息判专题化时，第一判的判定材料只有提问本身（+划线解析指代），纯净不受外部上下文影响。第一判判为"非专题化"时，若对话流里存在上一轮 AI 回复，自动降级把该回复作为辅助材料补考一次——提问自身看不出内核，可能只是信息不足：例"人生有什么意义"被忽略后，AI 回复抛出"意义是主观构建的"这个可辩观点，用户顺着追问"那照这么说呢？"，"你这么说"这个指代要上一轮 AI 回复才能解析。

降级判定的边界（钉死，防带偏）：
- 仅当这条消息在语义上承接上一轮 AI 回复（针对它追问、反驳、展开、质疑）时，AI 回复才作为判定材料参与：评估「提问 + AI 回复」合起来是否有可推进内核 → 有则专题化，无则不专题化。
- 不承接（全新话题、与上一轮 AI 回复无关）→ 维持非专题化。
- 纯反应（"嗯嗯""确实""明白了"）不构成承接 → 维持非专题化。
- AI 回复自身深刻不是判据——必须这条消息承接了它才参与判定。与"划线内容深刻不判专题化"同一哲学：划线没有"承接"这个动作，所以划线仅解析指代；AI 回复参与的前提正是"用户承接"。

上一轮 AI 回复经 assistantContext 字段传入判专题化，结构为 { content, selected? }。content 为回复文本，selected 为这条 AI 回复针对的划线（划线结构体 { text, book, chapter }）。降级判定的判定材料只用 content；selected 不参与判据。

降级判专题化（usedAssist）→ 入栈时**补入上一轮 AI 回复作背景轮次**：{ role: 'assistant', content, selected? }，selected 为它针对的划线。它是这场讨论的真正起点，缺了它后续同一性判断材料不完整。

适用边界：降级只在**空栈判专题化入口**启用。非空栈"换问题 → 判专题化"分支不带 AI 回复做降级——栈内已有当前讨论上下文，而"上一轮 AI 回复"属于被换掉的旧问题，新消息不承接它，降级只会误判。

**三个判断的职责**

- 判专题化：一条消息有没有可推进内核。同一判据，两个用法——空栈入栈（第一判纯净，必要时降级补考）、非空栈收口（不带 AI 回复，不降级）。
- 判同一性（新增）：新消息与栈内累积内容是不是同一个问题。二元等价判断，只判"是不是同一个"，不命名、不归类。识别接续不靠显式指代——用户对上一轮答复给出新观点、反驳或理解延伸（"不对，我觉得制度自身的惯性才是关键"）即使没有"那/这/它"，只要承接上一轮内容就是同一问题。
- 收口：没有独立的"讨论结束"判断。讨论没开新专题就一直留在栈里；出现新的专题化讨论才收口。收口动作把整栈桶打包为专题化讨论组 { ts, entries }，ts 取收口时间，entries 为栈内全部轮次。

**边界规则**

- 角度切换不切断：同一问题换对象、换书、换角度，是推进，不是新讨论。
- 问题意识转移才切断：用户追的问题本身换了（不再是同一个问题）。
- 用户解绑（取消引用转自由对话）：内容偏离原划线，不代表讨论结束，不切断。
- 中间穿插非专题化消息：不入栈、不切断。产品上正常回答，只是不累积进栈。
- 栈跨会话持久化：重启/换会话不弹空，用户可能下次接着聊同一问题。

**入栈 ≠ 转正**

入栈只是初判（可推进内核判据过即可），不等于转正进话题库。转正要过两道门槛：

- **专题化**（入栈时就过了）：问题有可推进内核。
- **转正**（收口后复核才定）：确认这次讨论真在推进——栈内有实质推进轮次（用户对 AI 答复的追问、反驳或新观点），不是只问了一句就没下文。

收口的讨论先进待归类桶（未转正草案，不进 L3 上下文），复核通过才转正。复核的证据是栈内已有的推进轮次，不靠未来的回响信号——防止一次性好奇混进话题库。收口不重新判专题化——栈的存在本身已由首条入栈时的专题化判断确立。

**栈内容与上下文**

栈条目 = { role, content, selected? }。role 为 user 或 assistant；content 为发言文本；selected 为划线结构体 { text, book, chapter }（可缺省）。user 轮次带自己的划线；assistant 轮次带它针对的划线。栈内累积内容作为同一性判断的上下文。长讨论需控制上下文量（窗口化/摘要，细则另定）。

**挂钩与派生母题延迟**

挂钩/派生母题不在收口时立刻做。专题化讨论形成后，会意系统持续观察推进，在合适时机（推进证据充分）为其挂钩已有话题或派生母题。这是对归类挂钩"待归类桶系统复核"的推广：复核时机从收口后移到观察后。

**归类挂钩**

专题化的讨论，会意系统判断它追哪个母题，三种结果：

- **勾住已有母题**（同一问题、不同书/不同角度）→ 挂钩：该话题的 question + 全部 threads 接进本会话后续上下文；固化时归入已有话题，追加一次推进（换角度聊同一问题视为推进，不新建话题）。
- **勾不住，但专题化** → **新话题候选**。收口后进**待归类桶**（draft：专题化讨论组 { ts, entries }），系统复核后转正，转正时会意系统派生其母题（动作③）。
- **拿不准** → 偏向路由。宁可过度合并不碎片化（碎片化是主要风险）；误合并可在复核时纠正。
- 待归类桶经**系统复核**才转正（收口后观察推进、证据充分时确认有可推进内核），防止一次性好奇进入话题库，不以"第二次回响"等表象信号为据。

会话中完整流程：

```
用户提问（材料 = 提问本身；有划线时划线仅解析指代）
  → 判专题化（动作①：有无可推进内核）——多数讨论停在这里
      ├─ 专题化 → 判挂钩（动作②，读读者会意 + 话题 motif）
      │     ├─ 勾住已有母题 → question + 全部 threads 接进本会话后续上下文（L3）
      │     └─ 勾不住 → 继续对话；收口进待归类桶，观察推进后复核转正（转正时派生母题）
      └─ 不专题化 → 留在本会话讨论，不进话题库
```

**反向自检**

会意由话题与画像沉淀而来，长期攒着也容易固化、看不见读者变化，故需重检纠偏。重检分两类：**一致性重检**——结构事件（新话题转正 / 话题合并 / 话题归档）后，查会意还贴不贴得住新积累的话题；新话题转正只是读者在同一问题意识下的正常展开，不构成漂移信号。**漂移重检**——由读者变化驱动（先兆 / 立场松动 / 判互斥），机制见下。

重检判定：现有话题仍贴合会意 → 不更新；不再贴合（话题积累超出会意解释范围 / 话题走向偏移）→ 重新表述会意，更新上下文与提示词。

重新表述会意以老朋友式定向问为手段：在后续回复中像老朋友一样直接问读者，邀请并鼓励他说说最近的经历，再结合最近经历重写会意。问法边界：

- **直接**：不借读书场合当由头，直接问私人生活。问的方向来自漂移观察（更愤世嫉俗 → 问是否遇到不公；变惆怅 → 问家里是否不顺）。
- **不强求**：可答、可拒、可岔开。拒绝不追问，但也不放弃——换角度、隔一段再轻轻问一次。
- **尽可能**：给假设不给断言（"是不是……"）；有具体抓手；留体面退路，拒绝不丢面子；分享须被接住——愿意说，靠上一次说出去的回报。
- **对象是读者本人**。

**漂移判断机制**（读者是否变了——对着读者本人测，不对着话题集。话题增多只是正常展开）。观察顺序与因果顺序相反：先兆（读者的处境变化）在因果上在先，但读者不会主动说出，CoRead 观察不到它。CoRead 能观察到的只有一件事——**立场松动**：读者对某个共享母题的立场从既定位置移开了；判互斥就是对立场松动的严格判定，一回事，判互斥是它作为判断的名字。

```
判挂钩"勾不住"（立场松动疑似）
  → 换词重链（前置，滤假警报）
      ├─ 换了词（同一根线；例：职场"领导一言堂"仍是"权力靠什么维持"）→ 兼容，勾住，不漂移
      └─ 重链不上 → 判互斥 = 立场松动（意识形态层：重构新旧方向的前提，比对母题）
            ├─ 不同母题（正交）→ 正常生长，开新话题，不漂移
            └─ 同一母题、前提互斥 → 立场松动成立，漂移候选——输出互斥轴 + 方向
                  ├─ 计数确认（数，不依赖读者开口）：沿互斥轴数"反复绕回新方向、不再绕回旧方向"，达标 → 漂移确认
                  └─ 定向问（问，依赖读者开口）：方向由互斥轴读出 → 取得明说 = 先兆（直接信任）→ 作重新表述之底——二元输出：拿到真话 / 没拿到（不解释，挂起或不再问）
```

判互斥的具体提示词：留空，待写。计数阈值（数到几次算确认、隔多久没回算"不再"）：待定。

**漏斗总纲**：

```
讨论 → 话题：会意系统判专题化（可推进内核）→ 判挂钩（勾住 / 新话题候选）→ 待归类桶系统复核后转正
话题 → 会意系统：会意由话题与画像沉淀而来
```

判定标准自下而上收紧：问题意识须能持续追问、跨书推进，一次好奇不够；会意由一类问题沉淀而成，单个问题不够。

**维护操作**（产品层只规定有哪些操作，不规定提示词细节）：

- `new_topic(motif, question, progress, thread)` — 新建：先由会意系统决定这条问题的根源性母题，再识别"用户在追的问题是什么"，写 question/progress。
- `route_to(topic_id, thread)` — 归入现有话题：判断新消息推进的是哪条问题意识，追加一次推进。
- `merge(topic_id_a, topic_id_b)` — 合并：两条问题意识实为同一条。
- `advance(topic_id, progress, thread)` — 推进：更新 progress，追加这本书的 thread。

维护时如何判断"用户在追什么"、如何写 progress/thread、如何防止知识点堆积——这些是直接喂给 LLM 的提示词素材，见操作文档 [topic-library-ops.md](topic-library-ops.md)。

## 6. 与现有记忆体系的边界

- profile.md = 用户的深层画像（身份、环境、成长、抱负 + 阅读品味）——不变，作为会意系统的佐证输入。
- soul.md = 你自己的立场与相处方式——不变。
- **话题库 = 讨论内容本身**（中间保真度），补上 profile/soul（高损蒸馏）和 journal（不可查询）之间的空档。
