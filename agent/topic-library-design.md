# CoRead 会意图：产品设计方案

> 状态：已实现（会意系统 agent/lib/* + 收口固化 + 图视图 extension/graph-view.js，AI-020）。核心机制与规则随设计推进定稿。
> 配套操作文档（直接喂给 LLM 的读写提示词素材）：[topic-library-ops.md](topic-library-ops.md)
> 用户情况与观念画像（总结式维护，不进头部）：[self-portrait-design.md](self-portrait-design.md)

## 1. 产品概述

CoRead 阅读助手的**讨论记忆层**。当前记忆按书隔离、只增不减；本产品改为**按知识点组织**：判专题化后的专题化讨论，收口时固化成一个**不可变的节点**（去聚合判同，2026-08-29 用户定调：每次固化都新建节点，同一个知识点被聊多次 = 多个节点，靠边连起来）；节点之间的**拓扑关系由用户自己的问题意识发展**——用户说"我想到我们之前说的『苏联的工业化史』，他和南美这里的工业化历史的有着不同的走向，为什么会有这样的不同的走向呢？"，系统记录一条从旧知识点到当前讨论的有向边。上下文历史的填充，按有向图从 root 到 recent 的路径组装。

一句话定位：会意图是**用户的知识点拓扑图**——节点是知识点（狭隘范畴），边是用户问题意识的轨迹。

## 2. 背景与问题

当前记忆策略是「按书隔离的全量历史」：每本书一段独立的对话历史，只增不减，每次提问把该书全部历史发给 LLM。

两个病根：

1. **跨书讨论被切碎**。真实案例：读《静静的顿河》第六章，从一段"老人认出故人"的划线聊出了「北欧福利国家的地基」「列宁工人贵族论」共 13 轮讨论，全被记在《静静的顿河》这一本书名下。换一本书再聊北欧，这些积累取不出来——书隔离把相关讨论按载体切碎了。
2. **token 无上限**。长度控制只在记忆固化环节生效，不作用于对话输入。阅读越久，请求越贵越慢，最终超出上下文窗口上限。

跨书检索此前有过一次雏形：只对已收束的结论做关键词匹配取回，因中文分词无法落地而整体禁用。

**为什么必须做**：短视频 / 算法推荐提供的是**碎片化知识点**——散乱、无关联、无主体，今天刷到明天忘。本产品从主体的困境出发，按"困境 → 问题意识 → 具体问题与知识点"组织：知识点是手段，问题意识是主线，主体是出发点。**问题意识属于用户**——系统不猜测用户追什么母题，而是让用户自己的引用（"我想到我们之前说的X"）把知识点连起来。

## 3. 目标

1. **用有向图替代机械的跨书联动**：旧方案对已收束结论做关键词匹配取回，因中文分词无法落地；图方案把知识点作为节点，用户引用作为边，换书重访同一知识点时整条路径自然带回。
2. **有界组装上下文，取代按书全量历史**：提问时按结构有界组装（章节窗口 → 图路径上下文 + 惰性截尾历史），替换"整本书历史全量回灌"。路径组装有界靠**选择**（只取（本轮命中 ∪ 本场栈引用）的 user 入边闭包，2026-10 口径，§5.4④）+ **12 节点上限**，不靠截断。（2026-09：L2 全书热点随 TAKEAWAY 机制移除；L1 本章标注讨论随后删除——61 轮历史窗口已覆盖单章讨论，L1 与历史重复，仅剩"未讨论标注弱提示"价值，宁缺毋滥。）

## 4. 功能设计：对话的上下文组装

本次改动：**优化对话的上下文组装**——由"整本书历史全量回灌"改为"按结构有界组装"。会意图（§5）是支撑机制。

### 4.1 用户提问时：组装上下文（读路径）

用户提问时，产品组装给模型的上下文 = 上下文层 + 系统指令（2026-09：TAKEAWAY 移除，L1/L2 删除）：

```
[SYSTEM 指令]                  ← AGENT.md（静态，2026-09 画像下沉后不再含画像/足迹）
[历史惰性截尾窗口]             ← 追加式历史（承载承接；本次消息的 enriched 形态只在当轮）
【背景档案】                   ← personaBlock（2026-09 下沉：易变内容在本次消息头部）
[图路径上下文]                 ← L3：（本轮命中 ∪ 本场栈引用）的 user 入边闭包，
                                  独立消息、排在【本轮消息】之前（机制见 §5.4④）
【本轮消息】[正在共读]《书名》章节 / [章节窗口] / 用户提问   ← anchored，恒为最后一条
```

各层规则：

- **画像下沉（2026-09）**：profile/soul/书籍足迹从 system 移到本次消息头部（`personaBlock()` 每次 say 动态读文件拼入）——system 只剩静态 AGENT.md，MEMORIZE 合并、会话结束固化（saveSessionMemory 重写 profile/soul）、新书足迹都不再重建 system；前缀缓存稳定：跨会话恢复历史后 `[静态S + 恢复历史]` 前缀可跨会话命中，画像变化只落在"本次消息"（本来每次都是新内容）。
- **历史跨会话恢复（2026-09 用户定调：跨会话需要旧消息）**：histories 是内存态、重启即空，跨会话承接会断裂——启动时（`restoreHistories()`）从 chat_input/chat_output 按配对规则（user 之后第一条不带 `_stream` 的 assistant 全文）重建每本书最近轮次，受 BUDGET 约束（恢复后走惰性截尾）；未配对的 user（等回复中）不恢复。

- **L3 图路径上下文（2026-10 最终口径）**：范围 = 跨书持久的知识点拓扑；数据来源 = 会意图（见 §5）；检索机制 = 引用解析（§5.4 ③）：用户发言中引用旧知识点（"我们之前说的X"）→ 命中节点；**种子 = 本轮命中 ∪ 本场实时栈已挂的全部引用**（收口前它们同属一场讨论，固化后会并进同一个节点的 user 边）；**闭包 = 种子 ＋ 沿 user 入边反向递归的全部上游**；内容 = `node.point` 标题行 ＋ excerpts **原话全文**，**不截断、不渲染 aliases**；作用 = 跨书联动的深度记忆，拓扑由用户问题意识驱动。**前端图高亮用同一组种子**，图上亮的即模型拿到的。**放置**：作为独立消息插在【本轮消息】之前（生成点前最后读到的永远是本轮问题）。**使用指令**：块头附"使用方式"——先正面回答用户问题；下文全是双方当时的原话，在此基础上延续/修正/反驳，给出实质推进，不复述原文；未提到的不要硬提。
- **历史惰性截尾（2026-09 定调）**：历史按**追加式**维护（每次请求 = 上次请求 + 末尾新消息）——前缀缓存只认"从头连续相同"，追加式命中率实测 95%+；每轮滑一条的窗口会让全部历史失配（实测 0%），不可取。输入有界靠**惰性截尾**：总 token 超预算（`HIST_TOKEN_BUDGET` = 64K，实测每轮 ≈643 token → ≈100 轮）时才从最老处整条切掉一批、切到裁剪目标（`HIST_TRIM_TARGET` = 40 轮 ≈25.7K，留 ~60 轮增长余量，避免"切完紧贴预算、追加一条又触发"——那样裁剪频率等于滑动窗口）；被切的是最老消息，长期价值由会意图 L3（引用时全量带回）/ 会意栈（跨会话持久化）/ profile·soul 兜底。token 估算按实测校准（1 字符 ≈ 0.62 token，样本 19.9 万字符 = 12.2 万 token）。窗口 40~100 轮覆盖单章讨论（3~10 轮）+ 承接余量；64K 占 1M 窗口 6.4%，请求体量主开关（历史占一次请求 92%）。

**关键性质**：L3 的语义判断只有一处——引用解析（用户发言里有没有引用、引用了哪个节点）。固化（§5.4 ②）发生在收口时，不进上下文组装。

## 5. 核心机制：会意图（有向图拓扑）

会意图是 L3"图路径上下文"（§4.1）的数据来源和支撑：它把用户追过的知识点从各本书的讨论里固化下来（每次收口讨论一个节点），节点之间的边由用户引用发展——让"换书再聊同一知识点"和"知识点之间的关联"都成为可能。

数据模型含三个对象，分属两层：**会意系统**（判断层）、**会意图**（存储层：节点 + 边）。画像层存于 profile.md（见 §6），不属会意图。

```
会意系统（判断层）        上下文 + 提示词（LLM 判断机制：判专题化 / 判同一性 / 问题归纳 / 固化派生〔point·能指〕 / 引用解析 / 段间衍生）
会意图（存储层）          有向图：节点（收口讨论的固化，不可变）+ 边（用户引用轨迹 + 段间衍生）
```

### 5.1 有向图结构：问题意识交还给用户

**节点** = 一次收口讨论组的固化（2026-08-29 用户定调：**去聚合判同，节点不可变**——每次固化都新建节点，建成后不并入、不追加、不改写；同一个知识点被聊多次 = 多个节点，靠边连起来）。节点之间没有系统预设的关系——**系统不判"哪个知识点追哪个母题"**。

**边** = 用户问题意识的轨迹。用户在讨论中主动引用旧知识点（"我想到我们之前说的X"），系统记录一条边：旧知识点 → 当前讨论所在节点。边的方向是**引用方向**（被引用的在前，当前的在后），整张图由此成为有向图；没有入边的节点是 root，最新讨论所在的节点是 recent。另有 derived 边（同一栈相邻段之间的对话连续性衍生，§5.4 ③）。

**问题意识交还给用户**：

- 系统的职责：判专题化（有没有可推进内核）、引用解析（用户引用了哪个节点）——都是**狭隘范畴**的判断，不涉及"母题"。固化只做派生（point / 能指）与新建节点，**不做聚合判同**（不猜"这属于哪个节点"——用户引用时自己说）。
- 用户的职责：用引用表达问题意识——"我想到我们之前说的X"，X 与当前讨论的关系由用户自己建立。

### 5.2 会意系统（判断层）

LLM 判断机制，三个动作：

- **① 判专题化**：判断一条讨论是否值得进会意图（有无可推进内核）。判定单元为讨论单元（栈），栈内另有判同一性（§5.4 ①）。多数讨论止于此。
- **② 固化（去聚合判同，2026-08-29 用户定调）**：收口的专题化讨论**直接新建节点**——不再判断"属于哪个已有知识点节点"（系统不猜：连"是不是同一个知识点"都不猜，等用户引用时自己说）。节点不可变：建成后不并入、不追加、不改写。
- **③ 引用解析**：用户发言中引用旧知识点时，找出指认旧知识点的说法并匹配节点。**一次发言可命中多个节点**，命中即取上下文（L3）并暂存；**建边在固化时**执行（当前讨论固化出节点后）；**不需要用户轻确认**（错边事后可删可改，§5.4 ③）。

存储（上下文 + 提示词）：

- **上下文**：判断素材——读者画像（经历 / 困境 / 欲望，§6）、相关节点与讨论、当前会意的沉淀。节点 id 不存储，判断时从会意图读取。
- **提示词**：各判定场景的指令——判专题化（含降级）、判同一性（实时栈 / 分段两种口径）、问题归纳、固化派生（point / 能指）、引用解析、段间衍生。

### 5.3 会意图（存储层）

会意图的存储：一张有向图，节点 + 边，跨书持久，是 L3"图路径上下文"（§4.1）的数据来源。文件级存储，一张图一个文件，便于读写与路径取用。

#### 节点 node

一个节点 = 一次收口讨论组的固化（节点不可变：建成后不并入、不追加、不改写，2026-08-29 用户定调）。

```json
{
  // 节点（会意图的 node）= 一次收口讨论组的固化，不可变；文件级存储
  // 注释规则：数组含义写在数组键行尾；结构体含义写在元素对象开头；其余为字段含义。
  "id": "n_xxx",                        // 节点 id：n_<base36 时间戳>_<进程序号>（nextNodeId 生成；示例为可读占位）
  "point": "北欧福利模式的历史成因及其不可复制性", // 知识点表述：解释落点形态，一句话（派生，§5.4②）
  "aliases": [                      // 数组：能指（2026-08-29 定调）——被卸除的能指：捡回 point 卸下的背景内容
    "北欧福利靠外部流量还是内部制度",  //   重心在背景对象，陈述完整（读这条能把握该背景内容）；
    "泵和阀"                        //   只捡讨论里展开过的；数量不限；可手动改写；引用命中不记词
  ],
  "discussions": [                  // 数组：本节点的专题化讨论（节点不可变，恒 1 条）
    {
      // 元素结构体（discussion）：一次专题化讨论。字段含义：
      //   question      该次讨论追的具体问题，收口时归纳成一句（§5.4① / lib/thread-question.js）
      //   book / chapter  讨论发生在哪本书 / 哪个章节
      //   excerpts      交锋轮次原文（数组，见下）
      "question": "一种秩序/制度靠什么维持得下去？维持条件是内生的还是外来的？能被再生产吗？",
      "book": "《静静的顿河》",
      "chapter": "六",

      "excerpts": [                 // 数组：组内全部交锋轮次原文（栈条目 user/assistant 全量配对，不截取；含无内核跟随轮次）
        {
          // 元素结构体：一轮交锋原文。字段含义：
          //   q  用户提问原文
          //   a  AI 回复原文
          //   t  轮次时间戳（毫秒）
          "q": "真正撑住北欧福利的不是技术是政治遗产…",
          "a": "你纠的这个点我认一半…",
          "t": 1786173499706
        }
      ]
    }
  ],

  "createdAt": 0,                   // 节点创建时间戳（毫秒，示例 0 为占位）
  "updatedAt": 0                    // 节点最近更新时间戳（毫秒，示例 0 为占位）
}
```

#### 边 edge

一条边 = 一次问题意识关联：要么是用户引用旧知识点（把当前讨论挂到旧知识点上），要么是对话连续性衍生（后一讨论从前一讨论思考中长出来，无显式引用也算）。

```json
{
  // 边（会意图的 edge）= 一次问题意识关联；有向：from = 被引用的旧知识点 / 被衍生的前一条讨论，
  //   to = 当前讨论所在节点
  // 2026-08-27 定调：去掉 quote 字段——追溯与删改触发均未实现，引用短语不落库
  // （不进 aliases、不存进边、不进解析协议——协议只返回命中 id）；衍生理由留在分割/收口的事件日志里。
  "from": "n_soviet_industrialization",   // 被引用的旧知识点节点 id
  "to": "n_south_america_industrialization", // 当前讨论所在节点 id（引用发生时该讨论固化出的节点）
  "kind": "user"                           // 边的来源：user（用户问题意识引用）或 derived（对话连续性衍生，分割/收口时判定，§5.4③）
}
```

#### 图的性质

- **有向**：边的来源有两种——user：用户发言里引用旧知识点（"我想到我们之前说的X"），引用解析命中后建边，**系统不猜引用**；derived：同一栈收口分段切出的**相邻段之间无条件建立**（2026-10 用户定调：去掉段间衍生 LLM 判定——同栈相邻段是对话连续性的机械产物，不替用户思考；关系语义仍以用户显式引用为准）。方向 = 引用/衍生方向。
- **root**：没有入边的节点（最早被追的知识点）。
- **recent**：当前讨论所在节点。
- **多引用**：一次发言可命中多个节点 → 上下文取**（本轮命中 ∪ 本场栈引用）的 user 入边闭包**，不截断（§5.4 ④）；多条 user 边在固化时一并建——**同一脉络的多个命中只按脉络上最后命中节点建一条边**（§5.4 ③，2026-09 用户定调）。
- **可纠正**：错边事后可删（remove_edge）、可改（update_edge），按 from+to 定位（§5.4 ③）。

### 5.4 判断机制

会意系统的三个动作在此定稿：① 判专题化、② 固化（去聚合判同，2026-08-29 用户定调）、③ 引用解析。先看**总览流程**（一张图讲完一次讨论的完整生命线），再分动作看细节。

#### 总览流程

流程图统一约定（流程性图示适用）：`→` 前进，`├─`/`└─` 分支，缩进表示层级，`——` 注释。

一次讨论从提问到入库的完整生命线（会话中 + 固化时）：

```
用户提问（材料 = 提问本身；有划线时划线仅解析指代）
  → 判专题化（动作①：有无可推进内核）——多数讨论停在这里
      ├─ 专题化 → 进入讨论单元（栈）继续追（同一性判断见 §5.4①）
      └─ 不专题化 → 留在本会话讨论，不进会意图
  讨论中：用户发言引用旧知识点（"我想到我们之前说的X"）
      → 引用解析（动作③）命中节点 → （本轮命中 ∪ 本场栈引用）的 user 入边闭包并入本会话后续上下文（L3）；
        引用挂消息（不建边——当前讨论尚未固化出节点）
  新专题化讨论到来 → 收口固化（2026-08-28 定调：收口即固化——新专题化讨论将旧的全体弹栈的
      那一刻，当场固化后分段：先判专题化、再判同一性，把栈内发散的具体问题细切成多个
      不可分割组 → 分割后每段归纳问题 → 固化（派生 point/能指 → 新建节点，节点不可变）
      → user 边；同栈相邻段间无条件建 derived 边 → 写图；关闭 / 启动恢复不做收口固化，
      只保存/恢复进行中的讨论）；画像补充（画像的补充时机，§5.5）
```

#### ① 判专题化与分割（固化后分割）

判专题化由会意系统执行（动作①），判据是内容：问题有无**可推进的问题内核**，与对话表象（交锋、回响等信号）无关：

- 有内核：问题是分析性的、关于机制/结构/关系的（"一种秩序靠什么维持"），能继续追问、可跨书应用。
- 无内核：一次性能答完的事实澄清（"这人物原型是谁"）、闲聊 → 不进会意图。

触发：**只有用户提问**。判定材料是提问本身——提问透露出用户真正追的问题；只有划线、没有提问不判：说明用户还没透出观点（可能只是标记重点、问历史背景或没读懂），没有观点可判。**有划线时，划线作为上下文附带，仅用于解析提问里的指代**（例："那这个怎么维持？"里的"这个"指划线里的什么）——指代解析后是机制问题的照常专题化；无划线可解析的指代短问保守不进；词义/闲聊/主观评价不因划线内容深刻而误判。

**收口固化（2026-08-28 用户定调）**：收口即固化——**新的专题化讨论将旧的全体弹栈的那一刻**，当场对弹出的旧讨论做**固化后分段**（lib/segment-stack.js：**先判专题化、再判同一性**——与实时栈分割（只做有限判断同一性，承接即同一）逻辑不同；无内核轮次**不做过滤处理**（不滤掉、不 ignored：它们不是知识点、不参与判同一，跟随并入当前组），把栈内发散开的具体问题细切成多个**不可分割**组）→ **分割之后**每段归纳问题 → **固化**（派生 point → 拾取被卸除的能指 → 新建节点；**节点不可变**——2026-08-29 用户定调：去聚合判同，不再判断"属于哪个已有节点"）→ user 边 → 段间 derived 边 → 写图；单段失败弃段记日志（宁漏勿误）；**收口固化整体失败（0 节点产出，如 API 持续故障）→ 被收口讨论压回栈顶，下次收口整体重试**。**关闭、启动恢复不做收口固化**：进行中的讨论留在栈里（topic_stack.json 跨会话持久化），讨论没被新专题化弹栈就不收口。

**栈状态机**（实时，逐条消息）：

```
空栈 + 消息 → 判专题化（可推进内核判据，入口过滤）
  ├─ 有内核 → 入栈（消息 + 划线 + AI 回复全带上）
  └─ 无内核 → 忽略，栈保持空（不会被切出来）
非空栈 + 消息 → 判同一性（与栈内累积内容比）
  ├─ 同一问题 → 入栈累积
  └─ 不同问题 → 判专题化
        ├─ 无内核 → 忽略（不入栈，不切断）
        └─ 有内核 → 收口固化：全部弹栈 → 固化后分段（先判专题化、再判同一性）
                     → 分割后每段归纳问题 → 固化（派生 → 新建节点，节点不可变）→ user 边
                     → 同栈相邻段间无条件建 derived 边 → 写图
```

**按书隔离**：栈按 bookKey 分组（bookKey = baseBookId | '_common'），**换书即换栈**——新书的讨论从空栈重新判专题化，旧书栈保持原位待回访；同一本书内换对象/换角度仍不切断。

##### 降级判定：AI 回复成种子（判专题化的补考）

判专题化第一判的判定材料只有提问本身（+划线解析指代），纯净不受外部上下文影响。第一判判为"非专题化"时，若对话流里存在上一轮 AI 回复，自动降级把该回复作为辅助材料补考一次——提问自身看不出内核，可能只是信息不足：例"人生有什么意义"被忽略后，AI 回复抛出"意义是主观构建的"这个可辩观点，用户顺着追问"那照这么说呢？"，"你这么说"这个指代要上一轮 AI 回复才能解析。

降级判定的边界（钉死，防带偏）：
- 仅当这条消息在语义上承接上一轮 AI 回复（针对它追问、反驳、展开、质疑）时，AI 回复才作为判定材料参与：评估「提问 + AI 回复」合起来是否有可推进内核 → 有则专题化，无则不专题化。
- 不承接（全新话题、与上一轮 AI 回复无关）→ 维持非专题化。
- 纯反应（"嗯嗯""确实""明白了"）不构成承接 → 维持非专题化。
- AI 回复自身深刻不是判据——必须这条消息承接了它才参与判定。与"划线内容深刻不判专题化"同一哲学：划线没有"承接"这个动作，所以划线仅解析指代；AI 回复参与的前提正是"用户承接"。

上一轮 AI 回复经 assistantContext 字段传入判专题化，结构为 { content, selected? }。content 为回复文本，selected 为这条 AI 回复针对的划线（划线结构体 { text, book, chapter }）。降级判定的判定材料只用 content；selected 不参与判据。

降级判专题化（usedAssist）→ 入段时**补入上一轮 AI 回复作背景轮次**：{ role: 'assistant', content, selected? }，selected 为它针对的划线。它是这场讨论的真正起点，缺了它后续同一性判断材料不完整。

适用边界：降级只在**空段判专题化入口**启用。非空段"换问题 → 判专题化"分支不带 AI 回复做降级——段内已有当前讨论上下文，而"上一轮 AI 回复"属于被换掉的旧问题，新消息不承接它，降级只会误判。

##### 三个判断的职责

- 判专题化：一条消息有没有可推进内核。同一判据，两个用法——空段开段（第一判纯净，必要时降级补考）、非空段"换问题"分支（不带 AI 回复，不降级）。
- 判同一性：新消息与当前段累积内容是不是同一个问题。二元等价判断，只判"是不是同一个"，不命名、不归类。识别接续不靠显式指代——用户对上一轮答复给出新观点、反驳或理解延伸（"不对，我觉得制度自身的惯性才是关键"）即使没有"那/这/它"，只要承接上一轮内容就是同一问题。
- 收口（切段）：没有独立的"讨论结束"判断。消息不换问题就一直留在当前段；换问题且有内核才收口。收口动作把整段打包为专题化讨论组 { ts, entries }，ts 取收口时间，entries 为段内全部轮次。

##### 边界规则

- **判定顺序钉死：先判专题化（入口过滤），有内核再判同一性**。无内核的消息直接忽略——**不会被切出来**；同一性只作用于有内核的消息之间。同一性优先于切段——一条消息只要承接当前问题（同一），就入段累积，**不再判它是否专题化**（例："再展开说说泵和阀""为什么？"单独看无内核，但承接当前讨论，入段——注意这里"无内核"是判专题化的结果，不是消息的先验属性，它必须先过判专题化入口才有资格谈承接）；只有被判为**非同一**的消息，才切段。
- 角度切换不切断：同一问题换对象、换角度，是推进，不是新讨论（换书由分组切断——消息流按 bookKey 分组；同一知识点的跨书延续由引用解析建边衔接，§5.4 ③）。
- 问题意识转移才切断：用户追的问题本身换了（不再是同一个问题）。
- 用户解绑（取消引用转自由对话）：内容偏离原划线，不代表讨论结束，不切断。
- 非同一且无内核的消息（穿插的闲聊、事实澄清、新话题寒暄）：忽略（不入段、不切断）。产品上正常回答，只是不累积进会意图。
- **跨会话承接**：消息流跨会话连续追加，下一次固化时整体分割——承接同一问题的消息（判同一性）自然合成一段；进行中的讨论随栈跨会话持久化（topic_stack.json 按书隔离），关闭 / 启动恢复不做收口固化（§5.4 ①）。

##### 入段 ≠ 固化节点

入段只是初判（可推进内核判据过即可），不等于固化。固化（§5.4 ②）在收口分段后执行：每段派生 point/能指 → **新建节点**（节点不可变，不做聚合判同）。

##### 段内容与上下文

段条目 = { role, content, selected?, cites? }。role 为 user 或 assistant；content 为发言文本；selected 为划线结构体 { text, book, chapter }（可缺省）；cites = 该轮次消息挂的引用命中 id 列表（会话中引用解析暂存，随栈持久化，固化时建 user 边）。user 轮次带自己的划线；assistant 轮次带它针对的划线。段内累积内容作为同一性判断的上下文（2026-10 改全栈追加：判同一性 prompt = 上轮输入 + 本轮新消息，前缀连续命中前缀缓存——滑动窗口（最近 8 轮）每轮滑 1 条导致判定输入几乎全部失配；收口分段/归纳问题等一次性场景仍用窗口，STACK_CONTEXT_ROUNDS 仅限那里）。**2026-10 实测修复**：全栈追加的 prompt 头部原带 `当前讨论（N 轮）`，N 每轮 +2，前缀在指令后即分叉——44 条真实栈 ≈25K token 每轮 0% 命中（平台未命中占比因此冲到 ~40%）；去掉计数字节后同形状实测 99.6% 命中。prompt 组装守则：**静态材料在前且头部字节不许随轮次变化（计数/时间戳/书签名一律不进静态段）**）。

#### ② 固化：专题化讨论 → 新建节点（去聚合判同，2026-08-29 用户定调）

> **术语（2026-08-28 澄清；2026-08-29 废除聚合判同）**：原"聚合（动作②）"指"聚合判同"这一局限步骤——判断讨论属于哪个已有节点，还是新建。**2026-08-29 用户定调：去掉聚合判同**——系统不再判断"这条讨论属于哪个已有知识点节点"（系统不猜：连"是不是同一个知识点"都不猜，等用户引用时自己说）。固化 = 派生 point → 拾取被卸除的能指 → 新建节点 → user 边 → derived 边 → 写图。

收口的专题化讨论（讨论组 { ts, entries }）分段后，每段**直接新建节点**：

- **新建节点**：派生 point（解释落点形态）+ 拾取被卸除的能指（aliases，重心在背景对象）→ 建节点（discussions 入库，excerpts 无损）。
- **节点不可变**：建成后不并入、不追加、不改写（手动修正走 update_node_point / update_node_aliases）。**同一个知识点被聊多次 = 多个节点**，靠用户引用（user 边）与同栈段间衍生（derived 边）连起来。
- **宁漏勿误**：无引用就孤立——漏了无痛（用户以后引用时自己连上）；**不再有"把两个知识点混进一个节点"的污染风险**（节点永不合并）。
- 固化发生在**收口时**（2026-08-28 定调：收口即固化——新专题化讨论弹栈旧讨论的那一刻当场固化；关闭/启动恢复不做），不进上下文组装。

#### ③ 引用解析：用户问题意识 → 边

用户发言中引用旧知识点（"我想到我们之前说的X""前面聊过的Y""上次那个Z"），会意系统找出指认旧知识点的说法并匹配节点：

- **命中与建边解耦（2026-08-27 定调）**：会话中命中只做一件事——把（本轮命中 ∪ 本场栈引用）的 user 入边闭包并入本会话后续上下文（L3，§5.4 ④），**不建边**（此刻当前讨论尚未收口固化出节点，to 节点不存在，会话也不需要边）；引用先暂存（**挂在触发引用的消息条目上**，随栈持久化，2026-08-28 定调）。**收口固化时**该讨论固化出节点后，收集组内消息挂的引用建边（源节点 → 触发回合所属节点；同 pair 去重）。建边时机不与命中同时发生。

- **LLM 介入（2026-08-27 定调：去掉字符串粗召回与覆盖判定，纯语义判定一次完成；材料只放条目身份，不放讨论原文；2026-08-29 加强：语义匹配，能指词面命中不是必要条件，内容线索是底线——空指不解析，不惯着用户）**：对**全量节点**做精判断（匹配依据：node.point、**node.aliases（被卸除的能指）**、节点内讨论过的问题；允许同义、简称、换表述、话题描述）。**内容线索是底线**：说法必须透露指认的是哪个知识点的信息——能指词、话题词、对讨论内容的描述；纯指示代词（"上次那个""那个问题"）或纯时间指代（"就和我们上次聊的一样"）没透露任何线索 → 不解析、不匹配。**指认意图**：只是恰好提到相关词、没有指认意图的，不是引用（讨论原文里偶然出现的词不算数，宁漏勿误）。多引用漏判**静默接受**（宁漏勿误：漏了无痛，用户以后会再引用）；只有输出非法（非 JSON/协议不符）才重试。**prompt 顺序（2026-09 缓存定调）**：节点列表（静态大头）在用户发言**之前**——前缀缓存只认"从头连续相同"，发言每次必变、放前面会让节点列表全失配（实测 0%），放最后则全命中（实测 92%+）。
- **一次发言可命中多个节点**：全部命中 → 上下文取（本轮命中 ∪ 本场栈引用）的 user 入边闭包（§5.4④）；收口固化时按触发回合所属节点建边——**同一条脉络上的多个命中，只按脉络上最后（recent 侧）的一个命中节点建一条边**（2026-09 用户定调：较早命中节点是后者的脉络祖先，多建边只是拓扑图视觉噪音）。**判据只认 user 边（2026-10 收窄）**：折叠的正当理由是"将来回溯后者时会顺带把前者带出来"，而 L3 只沿 user 入边走——若两个命中节点之间只有 derived 相连（同栈相邻段），回溯时带不出来 ⇒ **不折叠，两条边都建**（宁可拓扑多一条线，不能让 L3 丢来路）。折叠只在本次命中列表内做：绝不越过命中列表接到脉络更靠 recent 的节点——例：脉络 a→b→c，某段命中 a、b → 只建 b→该段节点，不建 c→该段节点（c 若被同栈另一段命中，由那段固化时自建自己的边）；脉络自身的边原样保留。
  > **2026-10 已定调（原 ⚠️ 待定项已解决）**：L3 改成只走 user 入边后，两处折叠的判据一并从 `isReachable`（user＋derived 混合）收窄为 `isReachable(..., ['user'])`——保留折叠、口径自洽。**实测副作用**：live 建边路径下，`pruneRedundantCitationEdges` 的替代路径原本都必须借道段间 derived 边（同一收口内新建节点之间不可能有 user 边），所以收窄后它在 live 路径上**实际上删不掉任何边**（等同一个不再生效的清理）。函数与判据保留（离线工具/将来建边方式变化时仍可用），不再承担"拓扑更净"的职责。
- **段间 derived 桥不再算覆盖**：同栈相邻段的 derived 边（A→B）不再构成"内容已被覆盖"的依据——一段命中节点若只能借 A→B 到达本段，其 user 边**必须保留**（删了 L3 就永远拿不到这条来路）。仍可删的情况只剩"只沿 user 边仍可达"（例：a→c→b 全是 user 边、c 沿 c→b→A 已能到达 A 时，c→A 冗余）。宁漏勿删：漏了只是多一条边，删错丢来路。
- **不需要轻确认**：命中即取上下文、暂存引用，不打断用户（"不用问，直接记"）。
- **命中不记词**：引用短语**不落库**——不进 aliases、不存进边、不进解析协议（协议只返回命中节点 id 列表）；aliases 是能指，节点创建时拾取，不随引用行为增长（2026-08-29 定调：aliases = 被卸除的能指，替代旧的"备选标题"；同日定调：追溯/删改触发未实现，edge 暂不落 quote 字段）。
- **未命中**：不取上下文、不暂存引用（用户可能记错或节点尚未建立；引用留在对话里，不强迫处理）。
- **错边事后可纠正**：remove_edge（删）、update_edge（改），按 from+to 定位（同 pair 多条边全部删/改；精确到单条的核对机制待追溯落地后另定）。
- 引用解析触发时机：**会话中**（用户发言时）——命中节点 → （本轮命中 ∪ 本场栈引用）的 user 入边闭包并入本会话后续上下文（L3），引用**挂消息条目**（随栈持久化）；**建边在收口固化时**（该讨论固化出节点，源节点 → 触发回合所属节点；同脉络多命中只按脉络上最后命中节点建一条边，在命中列表内折叠，不接列表外节点，2026-09 用户定调）。

**能指（aliases）的生成（2026-08-29 定调：捡回被卸除的能指）**：point 抓住落点，讨论中作为已知背景被带出的对象及其展开内容在 point 里退场——aliases 把它们**捡回来**，留在节点上为能指链的漂移**保留接驳材料**（系统不预设漂移方向；用户以后从这些对象滑向新话题时，节点能被命中）。节点创建时（固化直建）由 LLM 从 point + **全量讨论内容（不截取）**拾取：**重心在背景对象，不在落点**（不是 point 的换表述，重心与 point 对称）；每条把该背景内容说清楚（陈述完整，读这一条能把握这条内容，不许压缩成看不出内容的短提法）；只捡讨论里实际展开过的背景内容（不造面：不许发明讨论里没有的对象或角度、说法必须来自讨论本身）；覆盖展开过的背景面（合起来不丢面）；**数量不限**；可手动改写（update 入口与 point 同级）。

**derived 边（对话连续性，2026-08-28 定调：只存在于固化后的分段逻辑中；2026-10 用户定调：去 LLM 判定，改为无条件建边）**：同一栈内的对话必然有思维关系（实时栈分割只做有限判断同一性，栈内是思维连续的段，但具体问题可能发散）——收口弹栈后分段切出的**同一栈内相邻段之间无条件建立** derived 边（同栈相邻段处于同一条思维连续链，衍生是收口分段的机械结果，不再用 LLM 判定后一段是否从前一段思考中衍生；不替用户思考规定语义关系，user 边仍只来自用户显式引用）；**不比对上一个收口专题讨论**（不同栈之间不建边）。同 pair 已有 derived 边不重复建（去重，2026-08-30 评审 P5）。段间 derived 供拓扑承接与冗余 user 边折叠使用；用户若认为某条 derived 不成立，用删边入口处理（错边可事后删可改）。

#### ④ 上下文填充：一场讨论一次 user 闭包（2026-10 最终口径）

L3"图路径上下文"的组装规则（§4.1）：

- **种子** = 本轮引用解析命中的节点 ∪ **本场实时栈已挂的全部引用**（`collectStackCites(topicStacks[bookKey])`，见 lib/topic-stack.js）。理由（用户定调）：实时栈收口**之前**它们同属一场讨论——固化时同一段消息的 `cites` 会**一起变成同一个节点的 user 边**（`addCitationEdges(seg.cites, 新节点)`），所以它们不是两类东西。**前端图高亮用同一组种子**（`computeHitLayers`），于是「图上亮的」与「模型拿到的」严格一致。
- **闭包**：从种子沿 **user 入边** 反向递归的全部"来路"（这些引用所在的讨论当时各自引用过的更早知识点，带跳数）。调 `userAncestry(graph, seeds)`。
- **只走 user 入边**：`user` 入边的语义是"这场讨论当时引用了谁"= 这个节点的出身；节点不可变 ⇒ 来路边在固化那一刻定型，之后只减不增（且折叠判据只认 user 边，不会被 derived 借道的覆盖删掉）。**不走 derived 边**（同栈相邻段是判同一性切出来的"不可分割组"，按系统自己的判定就不是同一个问题）；**不走 user 出边**（去路：后来别的讨论引用它才长出来的边，不是这个节点的出身，且随图增长漂移）。
- **不截断**：节点内容（`node.point` 标题行 ＋ 全部 discussions 的 excerpts **原话全文**）全量进入。（上下文有界靠选择——只取闭包里的节点，不靠截断。）
- **不渲染 aliases**：point/aliases 是固化时为"引用解析 / 判同一性"生成的**索引**，不是语料；把目录当正文喂给主回复模型，它会自己补论证（幻觉），且那是系统归纳而非任何一方说过的话。`point` 只作标题行。
- **排序**：来路跳数大→小在前，**引用节点在最后**——块尾紧邻本轮问题。
- **放置**：整块作为独立消息插在【本轮消息】之前（`say()` 的 `options.l3`），不拼进问题正文。
- **上限兜底**：`L3_MAX_NODES`（12）——引用节点优先保留，其余由近及远。**这是体量的硬闸**：一场讨论引用多了，真实闭包可能到二十几个节点（实测 29 节点 ≈ 13 万 token），靠这个上限压到 12 节点 ≈ 4.3 万 token。
- **注入条件**：种子非空就注入（= 这场讨论引用过东西）——**不再要求"本轮必须有命中"**；当前讨论没有引用时由栈（§5.4①）承载。

**体量参考（实测同一场讨论的不同口径）**：闭包(本轮命中) 6 节点 / 2.3 万字 ≈ 1.4 万 token；闭包(本场全部引用) 12 节点 / 6.9 万字 ≈ 4.3 万 token（触上限）。旧实现（user＋derived 混合全祖先链）曾达 51 节点 / 29.1 万字 ≈ 18 万 token，且块尾是与当前问题无关的旧讨论，主回复顺着块尾答非所问（2026-09-26《大国大城》实例）——**块尾磁吸由"整块放在问题之前"解决，体量由闭包选择 + 上限解决**。

### 5.5 生命周期与维护

判专题化在会话中（用户提问时）；固化（动作②）在**收口时**（收口即固化——派生 point/能指 → 新建节点，不做聚合判同）；引用解析在会话中（用户发言时）。建图、固化、推进均由上述机制完成。

**三类决策时机**：

- **会话中（用户提问时）**：会意系统判专题化（可推进内核判据 + 讨论单元定栈范围，动作①）→ 用户发言引用旧知识点时执行引用解析（动作③），命中节点 → （本轮命中 ∪ 本场栈引用）的 user 入边闭包并入本会话后续上下文（L3），引用**挂消息条目**、**不建边**。用户谈到自己的情况/观念时维护画像（[self-portrait-design.md](self-portrait-design.md)；总结式追加，不进 profile，保持头部前缀稳定）。
- **收口时（收口固化，2026-08-28 用户定调）**：**新的专题化讨论将旧的全体弹栈的那一刻** → 固化后分段（先判专题化、再判同一性，细切发散的具体问题）→ **分割之后**每段归纳问题 → **固化**（派生 point → 拾取被卸除的能指 → 新建节点〔节点不可变，不做聚合判同〕）→ user 边（段内消息挂的引用按触发回合归属；同脉络多命中只按脉络上最后命中节点建一条边）→ 同栈相邻段间无条件建 derived 边 → 冗余 user 边清理（命中脉络上游被段间 derived 链覆盖则删，内容不变）→ 写图文件；单段失败弃段记日志（宁漏勿误）；**收口固化整体失败（0 节点产出，如 API 持续故障）→ 被收口讨论压回栈顶，下次收口整体重试**（讨论不因固化失败而从栈中消失）。
- **关闭 / 启动恢复**：**不做收口固化**——进行中的讨论留在栈里（topic_stack.json 跨会话持久化），讨论没被新专题化弹栈就不收口；启动时恢复栈 + 每本书上一轮 AI 回复（判专题化降级判定材料）。

**漏斗总纲**：

```
讨论 → 会意图：判专题化（可推进内核）→ 收口固化（新专题化弹栈旧讨论：固化后分段 → 每段归纳问题 → 固化（派生 → 新建节点，节点不可变）→ user 边 → 同栈段间衍生 → derived 边）
引用 → 会意图：引用解析（会话中命中：取上下文 + 引用挂消息）→ 收口固化时建边（源节点 → 触发回合所属节点）
```

判定标准自下而上收紧：知识点须能持续追问、跨书推进，一次好奇不够；user 引用边的建立只认用户自己的引用，系统不猜；derived 边只在分割/收口时判定对话连续性（§5.4③），宁漏勿误。

**画像的补充时机**

- 用户谈到自己的情况（家庭/工作/年龄/处境）或表露观念（立场/价值观/看问题的方式）→ 会话中即时总结进 **self-portrait**（[self-portrait-design.md](self-portrait-design.md)），画像语言陈述、不抄原话，不进 profile（头部前缀稳定，LLM 缓存命中率不受影响）。
- 推出来的（观察：反复在"制度的可复制性"上纠正我 → 可能反感宿命论）→ 本版不处理（日记只记用户说出口的；推断类内容留待后续设计）。

**维护操作**（产品层只规定有哪些操作，不规定提示词细节）：

- `create_node(point, discussion, aliases?)` — 新建节点（固化直建）：以讨论的问题归纳出 point（解释落点形态），并拾取被卸除的能指（aliases，重心在背景对象，§5.4③），建节点。**节点不可变**——建成后不并入、不追加、不改写（2026-08-29 用户定调：去聚合判同）。
- `add_edge(from, to, kind?)` — 建边：kind = user（引用解析命中后，记录用户的问题意识引用）或 derived（分割/收口时判定对话连续性）；**from/to 必须是已有节点**（不允许悬空边污染拓扑）。
- `remove_edge(from, to)` / `update_edge(from, to, new_from?, new_to?)` — 删边 / 改边：错边纠正，按 from+to 定位（同 pair 多条边全部删/改）。
- `update_node_point(node_id, point)` / `update_node_aliases(node_id, aliases)` — 改 point / 改能指：用户审阅时手动修正（固化后节点不被系统修改，改写走这两个入口）。
- `context_path(node_id)` — 取图路径上下文：root→recent 路径并集（混合边，不截断）。**保留给离线工具**；L3 组装自 2026-10 起改用 `user_ancestry(hit_ids)`（命中节点 ＋ user 入边来路闭包，§5.4④）；前端图视图的搜索/单击预览用同规则的本地副本 `extension/graph-view.js computePath`（命中态改走 `computeHitLayers`，见 §7.2）。
- `user_ancestry(hit_ids, max_nodes?)` — 取 L3 来路闭包（§5.4④）：只沿 user 入边反向递归，返回 `{id, node, hops, hit}` 列表（来路跳数大→小在前、命中在最后）。

维护时如何写 point、如何抽取引用——这些是直接喂给 LLM 的提示词素材，见操作文档 [topic-library-ops.md](topic-library-ops.md)。

## 6. 与现有记忆体系的边界

- profile.md = 用户的深层画像（身份、环境、成长、抱负 + 阅读品味）——不变，作为会意系统的佐证输入；用户自述不再进 profile。
- self-portrait = 用户情况与观念画像——新增；总结式维护（有新信息才追加条目，去重靠比对现有画像），不进头部上下文；区别于 profile 的合并式重写。
- soul.md = 你自己的立场与相处方式——不变。
- **会意图 = 讨论内容本身**（中间保真度），补上 profile/soul（高损蒸馏）和 journal（不可查询）之间的空档。

## 7. 前端可视化：会意图拓扑视图

> 状态：已实现（extension/graph-view.js，AI-020）。协议与实现随使用演进。

### 7.1 产品形态

侧栏「◎」按钮打开**全面板图视图**（Obsidian 式）：节点 = 知识点（point），边 = 用户问题意识轨迹（有向：user 引用 / derived 衍生）。两种状态：

- **观察态（一般情况）**：浏览整张拓扑图——滚轮缩放、拖拽空白平移、拖节点微调布局、悬停高亮邻接子图、点选节点看详情（point / 能指 / 节点讨论 / 元信息）、搜索定位（point / 能指 / 讨论问题）、图例（边种类、root、recent）。真实图为空时提供「载入演示拓扑」预览交互。
- **命中态（对话命中，2026-10 定调）**：会话中引用解析（动作③）命中旧知识点 → 高亮 = **一场讨论取一次 user 闭包**：
  - **种子** = 本轮命中 ∪ 本场实时栈已挂的引用。理由（用户定调）：实时栈收口**之前**它们同属一场讨论——固化时同一段消息的 `cites` 会一起变成**同一个节点的 user 边**，所以它们不是两类东西，不该画成两层两种圈。
  - **闭包** = 种子 ＋ 沿 **user 入边**反向递归的全部上游（该讨论引用过的旧知识点，以及它们各自引用过的更早知识点）。与 `agent/lib/knowledge-graph.js userAncestry` 同规则：只走 user 入边，不走 derived（derived 连的是判同一性判出来"不是同一个问题"的同栈相邻段）。
  - **含义**：图上亮的就是"这场讨论若收口成一个节点，那个节点的 L3 来路闭包"。**一种圈、一个含义。**
  - **边的两档 + 半亮档**：闭包**内部**的边分强（user 边，accent）/弱（其余，按边色画满）两档；**只有一端**在闭包里的边半亮（交代这些圈连到哪去了）；两端都不在的边压暗但保留可见。非高亮节点压暗到 0.45。若只画强边，无上游的引用会变成**无线孤点**、图失去结构（用户反馈"看不懂了"）。
  - **标识环：每个节点每类只画一道环**：引用节点 `r+3`／3px 满不透明 `recentMark`（动画期另画一道 `r+6→r+15` 渐隐外扩脉冲）；上游节点 `r+2.5`／2px `pathAccent`；路径起点 `r+6`／2px 虚线 `rootMark`。引用节点**只画深蓝环、不再叠靛环**（两道同色系环套一起就分不出哪个是引用）。
  - **图例只列两条**：`路径起点（无入边）`、`引用到的知识点`（2026-10 用户定调：不要那两层术语；有守卫测试钉住条数=2、文案里不许出现那两个词）。图例色**从 `COLORS` 取**，不硬编码十六进制（防止与渲染漂移——用户报过"颜色对不上"）。
  - 顶部横幅分行写明范围：「本场讨论引用到 N 个旧知识点 · 连它们的上游共亮 K 个」。
  - **已废弃的两版口径**：① user＋derived 混合边的 root→recent 路径并集——既不等于 L3 内容、也不等于历史内容，会让用户误判 AI 手里有什么（《大国大城》2026-09-26 实测：图高亮 46 节点 / L3 实际 8 节点，跑题在图上看不出异常）；② 把"本轮命中"与"本场已挂"画成两层两色——同一场讨论被拆成两类，用户看不懂。
  - **标签渲染（2026-10 用户反馈修正）**：① **可见性只看缩放**（`LABEL_MIN_SCALE = 0.5`）＋ 悬停/选中（单节点，不会互相压）——高亮节点不再"任何缩放都强制显示"：低于门槛时标签本就不参与碰撞避让（`_separateLabels` 同门槛），十几个高亮标签会叠成一团（用户原话"不会根据视野缩放显示"）。② 描述省略**只由缩放决定**（`labelShape(ratio)`：6/9/13/17/20 字 × 1/2/3 行，**渲染与碰撞盒子共用**同一套，原来两处各写一份嵌套三元）——**高亮与非高亮在同一缩放下截断完全一致**（2026-10 用户定调：高亮不该让省略逻辑变样；高亮只体现在圆环/亮度上）。唯一例外是**悬停/选中**：那是"点开这一个看"的临时聚焦，取满配。③ **底色按档位只画一次圆角矩形**：普通标签 `0`（不画底）／高亮标签 `0.5`（半透明，不再是不透明白板）／悬停·选中 `0.88`（真正的聚焦 pill）。**禁止用描边光晕**（`strokeText`）——描边字形是 canvas 最贵的操作之一，104 个节点逐帧各描一遍会把帧率打下去（2026-10 用户反馈"进图就卡"，其中一笔就是这个；有源码级守卫测试）。
  - **性能（2026-10）**：标签盒子与文字都按**视口剔除**（`LABEL_CULL_PAD = 140px`）——屏幕外的标签不进碰撞、不测字、不画字；标签避让在"两个盒子都被剔除"时整对跳过。`localStorage.coreadGvPerf = '1'` 后每 120 帧打印一次「物理/动画 · 标签避让 · 渲染」各阶段均值，用于定位卡顿来源。
  - **已知结构性开销（未改，待定）**：`_ensureLoop` 的常驻弹性使 rAF 循环在开图期间**永不停**（物理收敛后 `busy` 仍恒为 true）；每帧 = 2 次 `tickPhysics`（O(n²) 斥力 + 角分辨力）＋ 最多 12 轮 `_separateLabels`（O(n²) 四类碰撞）＋ 全量 `render`。n=104 时这一套本身就在边缘。可选治法：① 收敛且无交互时让循环空转（需在各交互入口补 `_ensureLoop()`）；② 斥力/碰撞上空间网格；③ 限制单图节点数。
  - **旧口径（user＋derived 混合边的 root→recent 路径并集）已废弃**：它既不等于 L3 内容、也不等于历史内容，会让用户误判 AI 手里有什么（《大国大城》2026-09-26 实测：图高亮 46 节点 / L3 实际 8 节点，跑题在图上看不出异常）。
  - **搜索 / 单击预览仍走混合边路径**（`computePath` 不传 kinds）——那是"浏览这张网"的语义，不是"AI 拿到了什么"。
  - 命中态仍按"链"分组展示，但**链按 user 来路分组**（`computeChains(..., ['user'])`）：命中节点常常互不相交（derived 邻段不再算同一条链），于是各成一条链——本次命中 3 个节点 → 3 条链（旧口径并成 1 条）。
  - **多脉络切换 = 真隔离（2026-10 用户定调）**：以前点「脉络 N」只改横幅和相机，其它脉络的节点照样亮着，等于切换没生效（用户反馈"看不懂"）。现在右下角是「**全部** / 脉络 1 / 脉络 2 / …」：点「脉络 N」→ **只激活该链**（`chainActiveSet` 返回 `{ids, strong, weak, stackOnly, roots, recent}`），其它脉络与"本场已挂"层一并压暗；点「全部」（默认，`_focusChain = -1`）→ 两层全亮。自动弹出动画的顺序：全部 → 逐条 → 回到全部 → 渐隐。横幅同步显示「只看第 N 条脉络（X 个节点）· 点「全部」看整轮」。
    > ⚠️ 隔离必须覆盖**全部三类标识**：节点外圈（`onPath`）、路径起点虚线环（`roots`）、引用节点脉冲（`recent`）。第一版只把「边」换成激活集，节点判定仍读全量 `hl.ids`，于是"观察某条脉络时其它脉络的节点照样高亮、照样脉冲"（用户复现）。现在**激活集恒非 null**（「全部」= hl 本身；隔离 = 该链），render/隐藏态/相机一律读它；并有源码级回归守卫（`test/graph-view-utils.test.js`：render() 内不许直接出现 `hl.ids/hl.roots/hl.recent/hl.edges`）。
    > 另：合并口径下一场讨论的引用常落在 4~6 条链上，逐条自动轮播要十几秒 ⇒ 自动轮播**只播前 3 条**（`CAROUSEL_MAX_CHAINS`），其余交给右下角按钮手动切换。
    > ⚠️ 单链预览的退出必须**恢复暂存**（2026-10 用户报"点开节点看详情，再退出时脉络选项不见了"）：单击节点 → `selectNode` 把消息级命中暂存进 `_savedState` → `highlightFrom(id, 'manual')` 把高亮换成**单节点混合路径**，此时 `hl.chains` 只剩 1 条 ⇒ 脉络按钮隐藏。原先只有"点空白"那一支做了恢复，`✕` 按钮走的 `closeDetail()` 只清 `sel` ⇒ 暂存的命中永远回不来。现在退出详情的逻辑**只写在 `closeDetail()` 一处**（✕ / 点空白 / 空态收起都走它）：有暂存 → 原样恢复（横幅 + 两层/链 + 相机）；无暂存 → `clearHighlight()`。另外 `recomputeHighlight` 的"是否命中态"判定从 `hl.stackOnly instanceof Set` 改成看 `hl.mode`（hit/picked/simulate）——search/manual 也带空 `stackOnly`，旧判据会把搜索结果误换成 user 来路闭包。
  - **命中自动弹出动画（自由模式与读书模式行为一致）**：图视图未打开时命中 → 自动弹出拓扑图 → 播放命中动画（横幅即命中通知）→ 单链停留约 3 秒后渐隐关闭；**多链时横幅轮播**（先展示第一条链的横幅并聚焦，停顿后聚焦下一条链切换横幅，全部播完再渐隐）。**聚焦语义**：高亮显示时相机聚焦当前链（「全部」时聚焦全部高亮节点）；横幅按钮隐藏高亮时取消聚焦（回到整体视图），恢复显示时重新聚焦。**多链时画布右下角出现悬浮脉络切换按钮**（全部 / 脉络 1 / 脉络 2 / …），点击切换隔离并取消自动轮播；用户交互后图保持打开不再自动关闭。

### 7.2 数据流与协议

- **图数据**：`GET /graph`（receiver）读 `agent/data/knowledge-graph.json`（会意系统固化产物：一张图一个文件，§5.3；文件不存在 → 空图）；图文件 mtime 变化 → SSE `graph-updated`，图视图开着自动重拉（重拉保留高亮，按 targets 重算）。`?demo=1` 返回演示拓扑（从 scripts/data/knowledge-graph-demo.json 的 events/demoOnly 重建），仅用于预览；`?free=1` 返回历史自由模式沙盒图（agent/data/knowledge-graph.free.json，§8；2026-11 起自由对话不再写沙盒，该入口只用于查看旧产物，文件不存在 → 回退正式图）。
- **命中事件**：agent 引用解析命中后向 chat_output.jsonl 写一行 `{"role":"graph-hit","hits":["n_xx",...],"reason":"…","bookKey":"…"}`（不落 _stream、不渲染为消息气泡，/history 过滤）；receiver 按既有通道转发为 SSE message；侧栏收到后计算路径并高亮。**路径计算在客户端做**（与 contextOf 同规则：入边反向可达并集 + 拓扑序），服务端协议只传命中 id 列表——图视图不依赖 agent 侧是否已实现建边，只要命中协议成立即可高亮。**命中按上下文隔离（2026-09 定调；2026-11 扩为按对话隔离）**：`bookKey` = 命中所属上下文（消息归属的书；自由模式 = 该场**对话 key**）；每个上下文的实时栈独立，命中脉络只在它所属的上下文显示——侧栏只接受与当前上下文匹配的命中（自由模式只收**当前对话 key** 的命中并并入引用窗体，读书模式只收当前书的命中），切书 / 切对话 / 切换模式时清理旧上下文的命中显示与挂起的命中动画。
- **实现载体**：extension/graph-view.js（自包含、无依赖、Canvas 力导向布局）+ sidebar.html 遮罩容器与样式 + receiver /graph 端点（graph-data.js 读取层）。

### 7.3 边界

- 图视图只读不改：不提供节点/边的增删改入口（维护操作仍走 §5.5 的产品层入口）。
- 命中事件与建边解耦（沿用 §5.4③ 定调）：图视图的命中高亮不参与建边。高亮范围 = 上一条的"一场讨论一次 user 闭包"（本场栈引用 ∪ 本轮命中 的闭包）。
- 演示拓扑与真实图互斥：载入演示后图视图标记「演示数据」，不污染真实图文件。

## 8. 自由模式（多对话沙盒，2026-09 定调；2026-11 扩为多对话 + 归档）

> 状态：已实现。用途：与读书模式并行的自由讨论空间——可新建多场**互相隔离**的对话；归档时默认把这场对话完整走一遍正常程序（保存记忆 + 收口进正式拓扑图），也可以取消勾选、不留任何痕。

**入口与上下文**：侧栏头部「自由」滑动开关进入/退出。自由模式 = 侧栏里与书籍无关的独立上下文（无章节/无划线/无引用）。每个自由对话 = 一个**独立 bookKey**（默认对话沿用历史哨兵 `__coread_free_mode__`，新建对话为 `__coread_free_<8hex>__`），对话之间的隔离**不新造机制**，全部复用既有的「按书隔离」一条链路：

| 隔离面 | 载体 | 说明 |
| --- | --- | --- |
| 消息归属 / 消息区过滤 | `bookId` = 对话 key → 气泡 `dataset.book` | 切对话 = 切 key，只显示该场对话的消息（§7.2 同款判定） |
| 会意讨论栈 | `topic_stack.json[<对话 key>]` | 跨会话持久化，每场对话各自的实时栈与 cites |
| LLM 会话历史 / 截尾游标 | `histories[<对话 key>]` / `hist_cursors.json` | 每场对话各自的上下文与预算截尾，互不污染 |
| 引用命中显示 | `graph-hit.bookKey` = 对话 key | 侧栏只接受当前对话的命中（§7.2 命中按书隔离） |
| 长期记忆 / journal | 对话 key 属自由 key → **不写 journal** | 默认不进 profile/soul；勾选「保存记忆」时按场单独合并 |

**对话生命周期**（切到自由模式的**那一刻**，消息区上方就出现「自由对话条」——当前对话 / ＋ 新对话 / ⤓ 归档全在这里，不用先点进二级入口；点当前对话开「自由对话」列表弹窗）：

- **对话条**：左侧 = 当前对话标题 + 对话总数徽标（一眼看出自由模式是多对话的），点击开列表；中间 = `＋ 新对话`（实心绿主按钮）；右侧 = `⤓ 归档`。这场对话还没说过话时，条下方多一行指路提示，并在消息区落一条**系统提示气泡**（归属当前对话 key、随切走摘掉、幂等不重复）说明"这是独立对话 / 怎么再开一场 / 归档能留什么"。
- **新建**：`POST /free-conversations {action:'create'}` → receiver 生成 key 落注册表（`agent/data/free-conversations.json`），侧栏切到新对话并清空消息区/引用窗体。
- **切换**：点对话条（当前对话标题）或列表项。侧栏摘掉上一场对话的气泡（消息仍按 key 留在存档里，切回来靠 `/history` 重渲染）、清空引用窗体与流式气泡、整链刷新上下文（头部标题/消息过滤/命中高亮）。
- **重命名**：列表里的 `✎` → 自绘输入弹窗 → `POST /free-conversations {action:'rename'}`。标题为空时用**首条用户消息**兜底显示（不写回注册表）；标题只用于显示与识别，不参与隔离。
- **删除**：列表里的 `🗑` → 确认后 `POST /free-conversations {action:'delete'}`，清注册表条目 + 该对话在 `chat_input/chat_output.jsonl` 里的全部消息。
- **跨面板恢复**：当前对话 key 存在 `chrome.storage.local`（`freeConvKey`）；面板重开/切换 tab 回到那场对话。key 已失效（被归档/删除）时落到最近有说话的对话（`/free-conversations` 的 `lastActive`）。

**归档（`⤓` 归档 / `/归档` 斜杠命令）**：归档 = 这场对话结束并删除。弹窗两项**默认都勾上**（归档默认就把这场对话完整走一遍正常程序），可以取消；侧栏把用户**最后一次的选择**记在 `chrome.storage.local`（`freeArchiveOpts`），下次打开沿用——取消是"这次先不留痕"，不是"以后都不留"：

1. **保存记忆**：把这场对话在 `histories[<key>]` 里的完整轮次交给 `saveMemoryFromTranscript`（与 `saveSessionMemory` 同一套 specs / 垃圾输出校验 / `.bak` 备份闭环），提炼进 profile.md / soul.md。**不走 journal checkpoint**——checkpoint 只对 `session_journal` 有意义。自由对话讨论过程中的【MEMORIZE】标记仍不合并（2026-11 用户定调：只在归档时统一提炼，与"对话中不固化"的边界一致）。
2. **收口进拓扑图**：这场讨论的实时栈跑**读书模式那套一模一样的正常程序**——`segmentStack`（判专题化 → 判同一性）分段 → 每段 `consolidateThreadQuestion` 归纳问题 → `consolidateDiscussion` 派生 point/能指、新建节点 → `addCitationEdges` 建引用边 → 段间无条件 `addDerivedEdge` → `pruneRedundantCitationEdges` 清理冗余 user 边，写**正式图** `knowledge-graph.json`。**产出是"分段那么多个"知识点节点，不是压成一个占位节点**（后者只存在于 2026-09 的测试沙盒实现里，已废弃——UI 文案也据此改写，不再说"收口为一个节点"）。不勾选则零产物（连线都不建）。
3. **归档即删除**：无论勾没勾，归档完成后清空该对话的讨论栈、LLM 历史、会话历史与存档消息；注册表留一条**墓碑记录**（`status:'archived'` + `archive:{memory,graph,note}`），在对话列表的「已归档」区显示这场对话的产物去向，可彻底删除。收口有产出时，系统气泡会把**具体知识点**列出来（最多 5 条），而不是只报一个数字。

**协议**：

- `GET /free-conversations`（receiver）→ `{ current, lastActive, active:[...], archived:[...] }`。每条含 `{key,title,messages,createdAt,updatedAt,lastAt,status,archivedAt,archive}`；`messages/lastAt` 由聊天存档实测（避免与真实落库漂移的冗余计数），排序按 `lastAt`。
- `POST /free-conversations`（receiver）→ `create` / `rename` / `delete`（只动注册表与消息，不动图与记忆）。
- `POST /free-archive`（receiver）→ 把归档请求写成一条 `chat_input` 记录（`content:'/归档'` + `bookId:<对话 key>` + `archive:{key,memory,graph}`），agent 轮询到即执行（记忆合并与收口固化要调模型，必须由 agent 做）。结果以 `role=system` 落 `chat_output` → SSE 回侧栏（toast + 系统气泡）。
- 注册表 `agent/data/free-conversations.json` 由 receiver（新建/改名/删除/活动登记）与 agent（归档墓碑）共写，两边共用 `agent/lib/free-conversation.js`；receiver 每 3s stat mtime 推 SSE `free-conversations-updated`，侧栏据此刷新对话条与列表（谁写的都能通知到）。
- 图视图在自由模式激活时切 `?free=1`（badge「自由模式」）；`knowledge-graph.free.json` 只是历史沙盒产物的只读入口（新版本不再有写入方，文件可随时手删）。

**不固化边界**（默认零污染）：

- 对话进行中不进正式图 `knowledge-graph.json`：实时收口的弹栈旧讨论**只结束不固化**，产物只在归档时（默认勾选）生成。
- 默认不进 `session_journal`（从而不进 profile/soul 记忆固化）、不驱动 self-portrait 画像、回复中的 MEMORIZE 标记不合并。
- 不绑定书级上下文：无划线 → 不写 `discussions.jsonl`、不建书籍目录；不改变「正在读的书」（`currentBookKey`）。
- 归档删除只清该对话自己的消息（`bookId`/`bookKey` 精确匹配），不碰其他书与其他对话；清理前留 `.bak-conv-delete`。

**限制**：自由对话的固化产物（收口进正式图后）才参与后续引用解析；取消勾选的那场对话内容随归档删除，不可恢复。
