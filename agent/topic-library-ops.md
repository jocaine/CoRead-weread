# 话题库读写操作说明（LLM 提示词素材）

> 状态：草稿，随讨论演进。
> **本文档内容准备直接作为 LLM 执行话题库读写时的提示词使用，措辞需精确、可执行，不是产品讨论稿。**
> 产品设计决策（三层记忆、生命周期、数据模型、三层上下文组装、检索机制）见 [topic-library-design.md](topic-library-design.md)。本文档只含"操作时怎么想、怎么判断"。

## 1. 思维模型：系统的两个方向

话题库底层是同一个系统，有两个相反方向，不同动作用不同方向思考：

- **自上而下（阅读方向）**：会意系统在底层，具体问题由它衍生。检索话题、组装上下文、判断"这次追问属于哪条问题意识"时，从上往下走——具体问题都源自同一会意系统。
- **自下而上（沉淀方向）**：具体问题凝聚成"这是我在追什么"的自我像。归纳会意系统时，从下往上走——从具体问题里看出共性，不凭空概括。

**基于真实内容归纳，不凭空发挥**：会意系统由具体问题归纳而来。LLM 做会意判断时必须依据话题库与画像里的真实素材（即它的上下文），不可自行发挥、不可拔高成空话。

## 2. 维护时问自己的三个问题

维护话题库（新建 / 归入 / 推进）时，用下面三个问题驱动，**不要用"这次聊了什么知识"驱动**：

1. **用户在追的问题是什么？** → 写 `question`
2. **这本书把问题推进到了哪？用户立场有没有转变？** → 写 `threads[].contribution`（交锋留下的未决质疑一并写在这里）
3. **这条问题现在整体走到哪？** → 更新 `progress`（现状一句，供列表与检索）

## 3. 禁止知识点堆积

条目保留的是"问题如何被推进"（观点交锋、证据带来的转折、未决点），不是关于某对象的百科事实（成因、机制、历史）。

`progress` / `threads[].contribution` 一律用"问题推进"的语言写。禁止写成"北欧福利的成因是 X、Y、Z"这类知识点清单；除非某事实改变了问题走向，否则不写。
