# 会意图读写操作说明（LLM 提示词素材）

> 状态：随实现同步维护（agent/lib/knowledge-graph.js 各判定提示词为准）。
> **本文档内容准备直接作为 LLM 执行会意图读写时的提示词使用，措辞需精确、可执行，不是产品讨论稿。**
> 产品设计决策（图结构、生命周期、数据模型、上下文组装、检索机制）原记于 `topic-library-design.md`，
> 该文档已于 2026-10 删除；如需追溯，从 git 历史取（最后提交 `612e79e` 之前）。
> 本文档只含"操作时怎么想、怎么判断"。

## 1. 思维模型：系统不做的事

- **系统不猜母题**：系统不判断"这个讨论追的是哪条问题意识"，不把讨论归入任何"母题"。会意图里的 user 引用边只来自用户自己的引用（"我想到我们之前说的X"）；derived 边 = 同一栈收口切出的相邻段之间**无条件建立**的对话连续性边（2026-10 用户定调：去 LLM 判定——同栈相邻段是思维连续链的机械产物，不替用户思考；不建边给用户语义关系定论，关系语义仍以用户显式引用为准）。
- **系统只做两件狭隘范畴的事**：
  1. 判专题化：这条讨论有没有可推进的问题内核（有内核 → 进会意图；无内核 → 不进）。
  2. 引用解析：用户发言里引用了哪个旧知识点（"我们之前说的X"），命中 → 取上下文 + 暂存（建边在固化时，§3）。
- **固化直建节点（2026-08-29 用户定调：去聚合判同）**：收口讨论固化时**不做聚合判同**——不判断"这条讨论属于哪个已有知识点节点"（系统不猜：连"是不是同一个知识点"都不猜，等用户引用时自己说）；每次固化都新建节点，**节点不可变**（建成后不并入、不追加、不改写；手动修正走 update 入口）。同一个知识点被聊多次 = 多个节点，靠用户引用（user 边）与同栈段间衍生（derived 边）连起来。
- **基于真实内容归纳，不凭空发挥**：节点 point、能指（aliases）都必须依据会意图里的真实素材（point + discussions 的 question/excerpts），不可自行发挥、不可拔高成空话。引用匹配只依据条目身份（point / 能指 / 问题表述），不放讨论原文（§3）。

## 2. 固化时做什么（2026-08-29 用户定调：去聚合判同，节点不可变）

收口的专题化讨论固化时，**不做聚合判同**——不再判断"这条讨论属于哪个已有知识点节点"（系统不猜：连"是不是同一个知识点"都不猜，等用户引用时自己说）。每次固化都**新建节点**：

1. **派生 point**：用一句话写这个知识点的狭隘范畴——解释落点形态（例：「孕育出哥萨克式角色的历史条件与契机」，不是「哥萨克式角色的身份政治」）。
2. **拾取被卸除的能指（aliases，2026-08-29 定调）**：point 抓住落点，讨论中作为已知背景被带出的对象及其展开内容在 point 里退场——aliases 把它们**捡回来**，留在节点上为能指链的漂移**保留接驳材料**（系统不预设漂移方向；用户以后从这些对象滑向新话题时，节点能被命中）。材料 = point + **全量讨论内容（不截取）**。判据：**重心在背景对象，不在落点**——不是 point 的换表述（重心与 point 对称）；每条把该背景内容说清楚（**陈述完整**，读这一条能把握这条内容，不许压缩成看不出内容的短提法）；**只捡讨论里实际展开过的背景内容**（不造面：不许发明讨论里没有的对象或角度，说法必须来自讨论本身）；**覆盖展开过的背景面**（讨论展开过几个背景对象/侧面就捡几个，合起来不丢面）；能单独指认；**数量不限**。
3. **新建节点**（discussions 入库，excerpts 无损）：节点**不可变**——建成后不并入、不追加、不改写（手动修正走 update 入口）。

**同一个知识点被聊多次** = 多个节点。节点之间靠边连：用户引用（user 边，§3）+ 同栈段间衍生（derived 边）。宁漏勿误：没引用就孤立——漏了无痛，用户以后引用时会自己把节点连起来；**不再有"把两个知识点混进一个节点"的污染风险**（节点永不合并）。

## 3. 引用解析时问自己的问题

用户发言里出现"我们之前说的X""前面聊过的Y""上次那个Z"这类引用时：

1. **引用的说法指哪个知识点？** → 匹配节点（依据 node.point、node.aliases 能指、节点内讨论过的问题；**不放讨论原文**）。**语义匹配**：说法的内容线索与节点身份是同一个知识点（允许同义、简称、换表述、话题描述），**能指词面命中不是必要条件**——描述性指认（"聊过的那个货币和政权信用的事"）也能匹配。**内容线索是底线（2026-08-29 定调：不惯着用户）**：说法必须透露指认的是哪个知识点的信息（能指词、话题词、内容描述）；纯指示代词（"上次那个""那个问题"）或纯时间指代（"就和我们上次聊的一样"）没透露任何线索 → 不解析、不匹配。**指认意图**：指认 = 用户用指认性表述提到之前聊过的知识点（"之前/上次/我们聊过/那个……"）；只是恰好提到相关词、没有指认意图的，不是引用。宁漏勿误。一次发言可以命中多个节点——全部记下，不需要用户确认。
2. **没匹配上？** → 不取上下文、不暂存引用。不强迫处理（用户可能记错、节点尚未建立、或线索不属于任何节点）。
3. **建边记录什么？（固化时执行）** → from = 被引用的旧节点，to = 当前讨论固化出的节点（新建，节点不可变），kind = "user"。**引用短语不落库**——不进 aliases、不存进边、不进解析协议（协议只返回命中 id）；aliases 是能指（新建时拾取），不随引用行为增长。**同脉络多命中折叠（2026-09 用户定调）**：一段固化节点命中同一条脉络（root→recent 路径）上的多个节点时，只按脉络上**最后（recent 侧）**的一个命中节点建边——较早命中节点的内容已被后者完整包含，多建边只是拓扑图视觉噪音。折叠只在本次命中列表内做，绝不越过命中列表接脉络更靠 recent 的节点（例：脉络 a→b→c，命中 a、b → 只建 b 的边，不建 c 的边——c 若被同栈其它段命中，由那段固化时自建）；脉络自身的边原样保留。
**段间 derived 覆盖再折叠（2026-09 用户定调）**：同栈相邻段 derived 边（A→B）建完后，一段命中节点若能沿 '上游→…→前一段命中脉络→前一段(derived)→本段' 到达本段，其内容已被本段上下文覆盖，对应 user 边删除（例：脉络 a→c→b，A 命中 {a,b}→b→A；B 命中 c 且 A→B 成立 → 删 c→B，与 b→A+A→B 等效）。c 在 b 下游（脉络 a→b→c）时不删；无 A→B（衍生判定不成立/失败）时不删（宁漏勿删）。

## 4. 禁止知识点堆积

节点保留的是"这个知识点被怎么讨论"（观点交锋、证据带来的转折、未决点），不是关于某对象的百科事实（成因、机制、历史）。

`point` 一律用"知识点的狭隘范畴"的语言写（例：「孕育出哥萨克式角色的历史条件与契机」，不是「哥萨克式角色的孕育有 A、B、C 三个条件」）。禁止写成知识点清单；除非某事实改变了讨论走向，否则不写。
