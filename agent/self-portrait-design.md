# CoRead 用户情况与观念画像（self-portrait）：产品设计方案

> 状态：设计方案（PRD 级），已实现。
> 定位：**对用户进行画像维护**——用户谈到自己的情况、或表露立场/价值观/看问题的方式时，**总结**为画像条目。

## 1. 产品概述

**一句话定位：替用户维护一份"情况 + 做过的事 + 对事件的思考 + 观念"的画像。**

用户在对话里谈到自己时——自己的情况（家庭、工作、年龄、处境）、实际做过的事、对自身经历的思考（想法/感受/心理活动），或表露观念（立场、价值观、看问题的方式）——系统把它们**总结**成画像条目（简洁陈述句），维护一份独立画像文档。

与 profile 的本质区别（用户定调 2026-08-17）：

- **不是合并式重写**：profile 每次会话结束把新旧内容压缩合并重写；本画像只在有新信息时**追加条目**，旧条目不动。
- **不进头部上下文**：本画像不进 buildSystemInstruction（头部前缀稳定，LLM 缓存命中率不受维护影响）。
- **不是原文截取**：条目是对用户情况/观念的**归纳总结**（画像语言），不抄原话、不流水账。

## 2. 背景与问题

此前方案（self-journal）把用户原话节选追加进日记。问题：

1. **原文截取不是画像**。用户要的是"对我的情况和观念进行总结"——可读、可维护的画像，不是原话流水。
2. **维护而非记录**。日记是原始素材（只增不改）；画像是维护对象（新信息追加、重复去除）。

同时保留核心约束：不进 profile（头部缓存友好）、不进头部上下文。

## 3. 设计决策：总结式画像维护

```
深层画像 profile.md（慢变量）    头部上下文，会话结束合并重写——缓存不友好
用户情况与观念画像 self-portrait.md（新增）  总结式维护：有新信息才追加条目，不进头部——缓存友好
```

- **捕获走总结**：用户消息进入 → 后台一次 LLM 调用，把本条消息里关于用户的四类信息**总结**为画像条目（situation / events / thoughts / belief）。
  - situation（情况）：家庭与亲属、工作、居住、年龄、经历、处境。
  - events（做过的事）：用户实际做过的事情与行动，带时间线索，**必须总结出发点/动机/对用户的意义**——用户对 CoRead 说出的完整的事都不是唠家常，行为背后是处境与意图（用户定调 2026-08-17）；只记表面行为是残缺总结。
  - thoughts（对事件的思考）：用户对自己经历/事件的想法、感受、心理活动、自我定位与行动意图——为某事犹豫、回忆、自我剖析、心境变化、对自己处境的认知。
  - belief（观念）：立场、价值观、看问题的方式、思维习惯——包括阅读讨论中反复坚持的立场。
- **去重靠比对**：判定时输入现有画像条目作参照，与已有信息重复的不再输出（维护，不重复堆积）。
- **存储**：`agent/self-portrait.md`，两节（## 情况 / ## 观念），每条 `- 陈述`。

## 4. 数据模型

```markdown
# 用户情况与观念画像（self-portrait）

> 说明与最近更新时间

## 情况（situation）
- 小时候父母离婚，随爷爷奶奶住，父亲常年不回家
- 已毕业在外工作，24岁

## 观念（belief）
- 认为北欧的制度优越性依附于国际位置，具有外部性，不可再生产
- 自认为是马克思主义者
```

## 5. 捕获机制（callLLM：判画像 + 总结）

会话中用户消息进入后，后台执行一次小 LLM 调用（独立判定，不干扰主回复），完成两件事：**判**（本条消息是否含用户情况/做过的事/思考/观念的新信息）+ **总结**（归纳成画像条目）。判定材料 = 用户消息 + **对话脉络**（该消息前后的 AI 回复）——动机/出发点往往在脉络里展开（例：用户先咨询"组织实践怎么学"、AI 回应后用户联系孙阿姨——动机在 AI 回复的语境中可见），从脉络归纳动机，AI 回复里的观点不属于用户、不总结 AI，但 AI 回应所揭示的用户意图要总结。

输出协议：`{"situation":["..."],"events":["..."],"thoughts":["..."],"belief":["..."]}`，都为空 = 无新信息，零写入。

总结原则（钉死）：

- **归纳成简洁陈述句**（一句一事），画像语言，不抄用户原话、不流水账。
- **只总结用户本人**：用户转述别人的事不记（除非带出用户自己的处境/态度）。
- **去重**：与现有画像重复的信息不输出（判定时带现有画像作参照）。
- **无新信息零写入**：闲聊、纯知识问答、寒暄、对 AI 回复风格的要求（soul 的领域）不总结。
- **读书讨论中的立场也算观念**：用户反复坚持或明确宣示的立场（"制度优越性依附于国际位置"）→ belief；一次性的临时提问不总结。
- **做过的事必须带动机**："8月从启辰之星离职——对现状不满，准备到别处看看"→ events；只写"离职"是残缺总结。
- **自我定位与行动意图进 thoughts**："认为自己处于无产者位置，想从阶级位置认知出发开始实践田野"→ thoughts。
- **动机从脉络归纳，不靠用户明说**：回填脚本同时读 chat_output（AI 回复），为每条用户消息挂前后 10 分钟窗口内的 AI 回复作脉络；实时路径记录最近一轮 AI 回复作脉络。已验证：孙阿姨事件的"从阶级位置认识出发的实践行动"由 LLM 从脉络自动归纳，与用户事后明说一致。

## 6. 维护机制（与 profile 的区别）

```
profile.md（旧路径）            每次会话结束：新旧内容压缩合并重写 → 头部前缀变化
self-portrait.md（新路径）      有新信息才追加条目；旧条目不动；不进头部
```

- 写入：新条目并入对应小节（按文本去重），重写文件保留头部说明。
- 频率：仅当判定产出新条目时写盘；无新信息零写入。
- 头部：`buildSystemInstruction()` 不含本画像，缓存前缀稳定。

## 7. 与现有记忆体系的边界

- profile.md = 用户的长期画像（合并式重写，头部上下文）——不变。
- self-portrait.md = 用户情况与观念画像（总结式追加维护，不进头部）——新增。
- soul.md = AI 自己的立场与相处方式——不变。
- 话题库 = 用户追的问题——不变。

## 8. 实现落点（已实现）

- `agent/lib/self-portrait.js`：judgeSelfPortrait（判 + 总结），输出 situation/belief；callLLM 注入；重试/解析容错与话题库同款。
- `agent/scripts/backfill-self-portrait.mjs`：全量历史数据（session_journal + chat_input）→ 逐条判定（带现有画像去重参照）→ 生成 self-portrait.md。
- `agent/index.js`：driveSelfPortrait 后台维护（不阻塞主回复，shutdown 等待）；两处消息入口挂接。

## 9. 待定项

- 条目合并与精炼：条目增多后是否定期压缩合并（注意：合并不等于 profile 模式，可低频整理）。
- 观念与话题库的界线：阅读讨论中的立场既进 belief 也影响话题库判挂钩，两者关系待观察。
